# 0.567.0

This release covers every change since 0.565.0. It's a fix for the **Drafts** window: the badge on each draft that counts matching notes could say "no duplicates" even when a note with the same title already existed. It now waits until Obsidian has finished loading your notes, checks every note in the folder, and says so when it couldn't check them all.

## Fixed

### Drafts: the duplicate badge no longer misses matches

- **0.567.0** — Each draft in the Drafts window has a badge counting the saved notes in its folder whose title matches the draft's first line. It could wrongly say "no duplicates". There were four causes, and all are fixed:
  - **It ran before Obsidian finished loading your notes.** A note Obsidian hadn't read yet was skipped. The badge now reads **"Waiting for index…"** until loading is done, then **"Checking…"**. A note Obsidian still hasn't read is checked straight from its file.
  - **It only checked the first 400 notes** in a folder, in no set order. It now checks all of them.
  - **It only checked notes sitting directly in the folder.** It now checks the same notes the folder's list shows, including ones in subfolders. Reserved folders such as attachments, archive and trash are still skipped.
  - **The wait could end too early.** Obsidian sends its "finished" signal after every edit, not only once at startup. The shared check that waits for Obsidian to load now ignores that signal until the first load is really done. This also makes the first-run Welcome window and the other startup checks that use it wait properly.
- If a note couldn't be read, or Obsidian took more than 60 seconds to load, a draft with no matches now shows **"Not fully checked"** instead of "No duplicates". Hovering it explains why.
- Badge text now starts with a capital letter ("No duplicates", "Checking…").
- In a very large folder, the badge may show "Checking…" a little longer than before, since it now reads every note.
