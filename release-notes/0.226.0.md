# 0.226.0

Composer work: a quick destination menu, and a new `+` mode that writes what you
type into an existing note instead of creating a new one — across Stashpads.
Plus a batch of scroll, mobile and importer fixes.

## 0.221.0 — quick destination menu

- Tapping the composer's destination button now opens a compact menu of recent
  folders instead of going straight to the full picker. One tap sets the
  destination and keeps composer focus, so the mobile keyboard doesn't drop.
- `More… (pick a note)` falls through to the full picker, unchanged, for when
  the target is a specific note rather than a folder.
- `Clear destination` appears at the top of the menu when one is already set.
- The current folder is excluded from the menu — a plain send already goes there.
- New `recentFolders` setting maintains an 8-entry most-recently-used list.

## 0.222.0 — `+` append mode

- Typing `+` as the only character in an empty composer opens the note picker.
  Pick a note and what you send next is appended to the bottom of that note's
  body on a new line, instead of creating a new note.
- Requiring `+` to be the entire composer value is what makes a single-character
  trigger safe: it can only fire as the first keystroke into an empty composer,
  never mid-sentence. Dismissing the picker leaves the `+` in place, so markdown
  `+ ` list bullets still work.
- A chip in the composer shows the bound target and clears it in one tap, so
  append mode is never invisible state.
- The target clears after one send. This fails safe — the worst case is an
  ordinary new note, rather than a thought silently buried in an old one.
- Append and its undo/redo run through the existing undo stack.
- New setting `composerAppendTrigger` (on by default) turns the trigger off.

## 0.223.0 — folder ranking, mobile checkbox, append persistence

- Split `lastUsedFolder` from `recentFolders`. One setting was answering two
  different questions — which folder opens on launch, and which folders are
  worth offering as destinations. Sending a note to another folder now feeds
  the recents list without relocating the folder Stashpad opens into.
- The mobile task checkbox moves from the row's footer back to the top meta
  row, ahead of the timestamp. The 0.120.0 three-section mobile row placed the
  footer in a full-width area under the body, which dragged the checkbox to the
  bottom of the note with it.
- The append target now persists per folder alongside the draft, through a
  single writer so the in-memory and stored copies cannot drift. Binding a
  target and reloading no longer silently turns the append into a new note.
- The append picker returns focus to the composer when Home is picked.

## 0.224.0 — completion scroll, mobile menus, pinned folders, import dedup

- Toggling a task complete repainted the whole list, unlike the colour and
  mark-as-task paths. It now repaints in place, and suppresses the redundant
  follow-up re-render whose scroll-anchor restore is what moved the list.
  A full render still happens when the change is genuinely structural — when
  "hide completed" is on, or a recurring task rolled, spawned or archived.
- Task submenu items now close the root menu. Obsidian dismisses the menu an
  item belongs to, but on mobile the parent sheet stayed up, covering the row
  just acted on.
- Pinned folders now rank first — in the order shown in the folders panel — in
  the folder switcher, the destination picker and the quick destination menu.
  In the switcher, pins outrank the last-used folder.
- Pinned folders no longer appear in the folder panel's top section, which is
  now pinned notes only and titled accordingly. Folder pins keep their meaning
  through the ranking above; the section had mostly restated the list below it.
- Stashpad-app import: the set of already-imported ids was captured when the
  importer opened, so pressing Import twice duplicated everything despite
  "Skip notes already imported" being on. It is now read fresh on every parse,
  combined with the ids written during the current session — the metadata cache
  has not parsed those files yet, so a cache-only lookup still missed them.

## 0.225.0 — cross-folder append and prepend

- The append picker now offers notes in any searchable Stashpad, turning the
  composer into "start typing wherever you are, land the text in the right
  existing note" — the same move the destination picker makes for new notes.
- Prepend mode writes directly after the frontmatter block rather than at the
  end, measured from the metadata cache with a regex fallback. Flip between
  append and prepend from the chip menu.
- The chip shows `Folder ▸ Note` for cross-folder targets, so two notes sharing
  a title in different Stashpads are distinguishable.
- Attachments staged in the composer are rehomed to the target's folder before
  a cross-folder write; otherwise the link points into the origin folder's
  attachments and strands.
- Cross-folder writes report via a notice, since the affected row is not on
  screen.

## 0.226.0 — filename sync and submenu dismissal

- Cross-folder writes re-slug the target's filename inline instead of relying
  on the file-modify handler, which ignores paths outside the active view's own
  folder. A prepend changes a note's first line, so without this the filename
  kept describing text that had been replaced. Undo and redo re-slug too, and
  the same-folder case is now immediate rather than waiting on a debounce.
- The task submenu is closed explicitly alongside the root menu. On mobile the
  submenu is the sheet covering the row, so its dismissal should not depend on
  close-cascade behaviour.

## Internal

- Backlog housekeeping: logged RSS support as a parked long-term goal and
  reframed the carry-a-draft-between-folders request around the quick
  destination menu, which addresses the same need without moving drafts.
