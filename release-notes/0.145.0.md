# 0.145.0

## Default delete → Stashpad's own Trash (0.145.0)

- A default delete (in a folder where encryption is **off**) now sends the note — and
  its whole subtree — to Stashpad's own per-folder `trash/`, recoverable from the
  **Trash view**, instead of Obsidian's system trash. The deleted subtree is written
  as an unencrypted `.stashpack` bundle alongside a metadata sidecar recording its
  origin folder, so **Restore** puts it back exactly where it came from.
- In a folder where encryption is **on**, deletes continue to route to the encrypted
  trash as before.
- The explicit **"Delete selection to Obsidian's trash (unencrypted)"** command, and a
  folder's **"Follow Obsidian's trash"** preference, remain the only ways to send a
  delete to Obsidian's native trash.
- **Undo** brings a deleted note straight back, and the Trash view's **Restore** /
  **Restore all** now cover both plaintext and encrypted items. Plaintext-deleted
  bundles are listed grouped by their origin folder.

## Hard-wipe for retired key material (0.144.1)

- When retiring the legacy encryption keyfile, you can now choose to **permanently
  hard-wipe** the parked key material instead of keeping a recoverable backup — for
  when you want the old keys gone for good rather than archived.

## Single-key symbol hotkeys fire (0.144.0)

- Fixes a hotkey bound to a shifted-symbol key so it actually triggers. Most visibly,
  the two-note **merge** command's default `&` hotkey was silently dead; single-key
  symbol bindings like `&` now fire correctly, on any keyboard layout that produces
  the character.
