# 0.264.0

## Link previews

A URL in a note is just a URL — whatever made it worth saving lives on the
other end of it, and disappears the moment the page does. Stashpad can now
fetch what a page says about itself and keep that text **in the note**, where
Obsidian indexes it and search can find it years later.

Three commands:

- **Add link previews to the selected note(s)** — fetches every link in those
  notes that doesn't already have one.
- **Refresh link previews on the selected note(s)** — refetches and replaces,
  for when a page has changed or the first attempt was poor.
- **Backfill link previews across every Stashpad folder** — a one-off sweep for
  links you saved before any of this existed.

Each link gets a collapsed callout at the bottom of the note with the title,
source, date and description. Collapsed, because a note with several links
would otherwise be mostly preview.

### It won't overwrite your edits

Previews are best-effort — sites publish whatever they feel like, and some
publish nothing useful — so they are meant to be corrected by hand. Because of
that, **a link that already has a preview is left completely alone**. Only
*Refresh* replaces one, and it says so before it does. Nothing you type into a
preview will be quietly regenerated away.

Links that can't be fetched get a short block too, saying what went wrong.
That's deliberate: it's somewhere to type the details in yourself, and a record
that the link was tried at all.

### Backfill tells you what it's in for

Sweeping an archive can mean thousands of requests, so the backfill counts the
work first and tells you — how many links, across how many notes, and roughly
how long — before fetching anything. It defaults to *Not now*. Notes are only
ever appended to.

### Settings

**Link preview callout style** picks which Obsidian callout type is used, and
**Pause between link fetches** controls how gently sites are treated during a
sweep (300ms by default — raise it if a host starts refusing).

### Worth knowing about YouTube

YouTube publishes only the **first ~160 characters** of a video description in
the metadata every site reads. So a video preview gets the title, channel and
date in full, and a description that stops mid-sentence. That's a limit at
YouTube's end rather than something to configure — capturing full descriptions
needs a different approach, which is being looked at separately.
