# 0.274.3

A performance fix for the new aggregate views, plus two smaller fixes.

## Performance: aggregate views don't recompute in the background

The 0.274.0 aggregate views (All notes index, Due calendar, Activity heatmap)
each rebuild by scanning every Stashpad note — and, for the heatmap, the whole
action log — whenever the vault changes. Those refreshes were firing even when
the aggregate tab was in the *background*, so editing, dragging, or applying
changes in the main note view triggered a full vault-wide recompute of a tab you
weren't even looking at, which made the main view feel slow and laggy.

Now a background aggregate tab only marks itself out of date on a vault change and
recomputes **once**, when you switch back to it. A visible aggregate tab still
updates live as before (with edits coalesced over a slightly longer window so a
drag that moves several notes rebuilds once instead of repeatedly).

## Trash view sorts by most-recently-deleted

The Trash tab now opens as one flat list, newest deletion first, instead of the
by-folder grouping — because "what did I just delete?" is the usual question. The
mode chips still switch to By folder / Encrypted / etc.

## Aggregate tab titles

A freshly-opened aggregate tab (All notes, Due calendar, Task timeline, …) now
shows its correct name in the tab and header immediately, instead of briefly
reading "All encrypted" until you switched away and back.
