# 0.261.0

## The duplicate-id modal can now resolve duplicates, not just report them

When two notes share an id, one of them is hidden from the list even though the
file is still on disk. Stashpad detected that and showed you a list — and then
left you to open each copy in turn, work out which was which, and delete the
loser by hand somewhere else.

**Every row now has a Discard button.** It moves that copy to the trash,
respecting your own "Deleted files" setting, and Undo in the list brings it
back. There is a confirmation step first, defaulting to *Keep it* — these files
are hard to tell apart, which is exactly when a one-click delete is the wrong
shape. Only the note is trashed, never its attachments: a duplicate is a copy,
and its attachments are usually the very same files the copy you are keeping
points at.

**Every row tells you what differs, without clicking anything.** Each hidden
copy is compared up front and labelled:

- **same content** — body and real note state both match; nothing is lost by
  discarding it
- **text differs** — the body is not the same; read it first
- **N fields differ** — same body, but attachments, due date, colour or tags
  differ
- **text + N fields** — both

with **· newer** added when the copy is the more recently modified of the two.
Previously this took a Compare click per copy.

**Sync conflict copies sort to the bottom** of each group and are marked
*conflict copy*, since they are the likeliest thing to discard. They are still
worth reading — a conflict copy can hold the newer edit — but they no longer
sit mixed in among the others.

**Comparing no longer loses your place.** Going into Compare and back used to
return you to the top of the list, which meant finding your position again
after every single comparison.

## Fewer notifications about it

The warning that notes are hidden by duplicate ids was shown once **per open
Stashpad tab**, so three tabs meant three identical warnings about one
vault-wide problem. It is now shown once.

## Easier to read

The modal is wider, file paths wrap instead of needing to be scrolled
sideways — the filename is the part that tells two copies apart, and it was the
part being cut off — and the action buttons moved to the left, where long paths
can no longer push them out of reach.
