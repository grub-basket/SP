# 0.211.1

A data-safety pass, an editor fix that had been quietly undoing your work, and a much
better importer. If you only read one line: **one of these was a bug that could make an
encrypted folder permanently unopenable**, so this is worth updating for.

## Your data

- **Encrypting a folder no longer destroys the key that opens it.** "Encrypt with
  Stashpad" on a non-Stashpad folder bundled the folder's own key file into the
  encrypted bundle and then deleted it. Nothing looked wrong at the time, because the
  key stays in memory for the rest of the session — the folder only became
  unopenable after a restart. Fixed, with a second guard that refuses to delete
  anything if the key is not still readable.
- **A damaged settings file no longer resets your settings.** If `data.json` was
  truncated (a crash or a sync landing mid-write), Stashpad read it as empty, showed
  defaults, and then saved those defaults over the damaged file — taking your hotkeys,
  templates, colours and encryption identity with it. It now keeps a copy of the
  damaged file, tells you, and refuses to save over it for the rest of the session.
- **Your settings survive using two machines.** Only 8 of ~94 settings were protected
  from a stale write by another instance. Rebinding hotkeys on a laptop could be
  reverted by the desktop's next save. Every setting is now protected, and settings
  that are really maps (drafts, per-folder templates, colour aliases) merge entry by
  entry, so two machines editing different entries keep both.
- **The editor no longer reverts changes made while it was open.** Saving used to
  write back the note's frontmatter as it looked when the editor opened, undoing
  anything that changed meanwhile — including Stashpad's own updates, so a save could
  quietly move a note back under its old parent. It now writes only your text onto the
  current frontmatter, and asks first if the note's body changed elsewhere.
- **Saving a note with damaged frontmatter is refused** rather than stripping its id
  and detaching it from the tree.
- **Repeating tasks no longer risk colliding with an existing note's id**, which could
  make one of the two disappear from the list.
- **A parent loop can no longer freeze Obsidian.** If two devices moved notes in
  opposite directions, the resulting loop could make the next delete or paste hang.

## The importer

- **Handles the old Stashpad desktop app's export.** That app writes the top parent
  with no bullet and no indent, its children with a bullet but still no indent, and
  only starts indenting at the third level — so imports came out flattened. There is
  now a "Pasted from the old Stashpad desktop app" toggle for exactly that shape, and
  indentation of any size (one space, two, four, tabs) is detected properly.
- **Per-row controls**: set a colour per line, and nest a line under the one above (or
  move it out) when no toggle gets the shape right. Your adjustments survive editing
  the pasted text.
- **It no longer closes when you press Import**, so your text and settings stay put for
  a second pass. The confirmation now carries a "Show imported notes" button.

## Elsewhere

- **Reveal selected notes in Finder** (or your file manager), from the command palette
  or the right-click menu. Notes from the same folder open one window, not one each.
- **Cross-vault copy and paste tells you when it is ready.** Preparing the transfer
  takes a moment on a large selection, and pasting before it finished silently did
  nothing. It now says when it is ready, says when it failed, and the source vault
  offers to remove the originals without needing you to click into it first.
- Notices name both the source and destination vault, and put names in bold.
- **`[[   ]]` with only spaces inside is no longer treated as a link** and hidden.
- Notes created in the same instant now sort the same way on every device.
- **Recurring tasks are labelled experimental**, in the app and the README. They work,
  but they are not thoroughly tested across time zones, missed occurrences and
  multi-device sync — please do not hang a real deadline on one yet.
- New **"Diagnose selection"** command for when Select All looks like it missed
  something; it reports where the count actually drops and copies a report.
