# 0.140.15 — Deep review pass, part 2: view internals, settings, keystore, search, hotkeys

A continuation of the multi-wave correctness/security review (0.140.1–0.140.8),
now covering the largest and most sensitive files: the main view's mutation and
render paths, the settings tab, the key-persistence layer, the note picker, and
hotkey matching. Every fix was found by review and verified before landing.

## Main view — mutations & undo (0.140.9 – 0.140.10)

- **0.140.9**
  - Merging a note into its own selected child no longer writes a self-referential
    `parent` (which surfaced as a broken tree on redo); the kept note is
    re-parented correctly and only moves that actually happened are recorded.
  - Merge now guards a malformed frontmatter block on the kept note (previously it
    could slice off the note's own `id`).
  - Undo/redo no longer re-creates a note that was slug-renamed since the action,
    which could otherwise produce two files sharing one `id`.
  - A debounced render firing after the view closed no longer rebuilds detached UI
    or leaks a document-level key listener.
  - Cloning a parent together with one of its descendants no longer duplicates the
    descendant, and a clone that fails partway still registers an undo entry.
  - Undoing "create note" no longer overwrites text you've started typing in the
    composer.
  - The plaintext-archive action gained a proper redo (it was undo-only before).
- **0.140.10** — Undo/redo now resolve the target file by its stable id (not the
  path captured when the command ran), so an undo still works after the note's
  file was renamed by a slug change.

## Settings (0.140.11)

- The two destructive encryption-removal choices — "delete all locked content"
  and "discard encrypted trash" — now focus Cancel, so a reflexive Enter can no
  longer irreversibly destroy content.
- The author-name field no longer renames every author stub file on each
  keystroke; the vault-wide rename now waits until you commit the field (blur or
  Enter). Role and department behave the same way.
- The notification-history limit is applied on commit (blur/Enter) and rejects
  negative/invalid input, instead of applying each intermediate digit (which
  could transiently truncate the stored history).

## Views (0.140.12)

- The right-hand detail panel no longer accumulates rendered-markdown
  sub-components across refreshes, and it keeps live-updating after the shown note
  is renamed (by a slug change or an external sync).
- The aggregate views refresh on more of the changes that affect them — encrypted
  bundle renames, and plain notes being archived/un-archived — not just encrypted
  bundle create/delete.

## Key storage (0.140.13)

- A vault keyfile that is momentarily unreadable (e.g. a sync client mid-write) is
  no longer mistaken for "no encryption set up"; first-time setup and the legacy
  migration now refuse to overwrite it rather than replacing it with a fresh
  single-key file.
- Per-folder key lookups are hardened against folders named like built-in object
  properties, and tolerate an incomplete key entry instead of erroring.

## Search / note picker (0.140.14)

- Date filters with a time component (e.g. `before: [2025-01-15 14:30]`,
  `on: 2pm`) now parse correctly instead of being silently ignored.
- An unparseable date value is kept as ordinary search text rather than being
  dropped — a mistyped `before:` no longer turns the query into "match
  everything".
- `yesterday` / `tomorrow` / the `on:` day window use calendar-day arithmetic, so
  they stay correct across daylight-saving transitions.
- Creating a note from the picker strips filter qualifiers from the title (so
  `in: [work] meeting notes` creates "meeting notes").
- Opening a folder from the folder sub-picker no longer re-opens the search modal
  on top of it, and cross-folder breadcrumbs render correctly after excluded
  folders are merged in.

## Hotkeys (0.140.15)

- Hotkey matching now identifies letter and digit keys by physical key, matching
  how the recorder stores them — so bindings that use **Shift+digit** or (on
  macOS) **Alt/Option+letter** actually fire. Previously these were recorded but
  never matched. Non-US keyboard layouts are handled consistently as a result.
