# 0.260.0

## The note you are inside is now a row in its own list

Drilling into a note showed that note as a header above the list. It looked
like part of the list without being part of it — you could not reach it with
the keyboard, could not select it, and commands that act on "the selected
note" could not see it at all. Right-clicking it and choosing an action could
quietly act on one of its children instead.

It is now a **row**, pinned to the top of the list.

- **Arrow keys reach it.** Pressing ↑ from the first child lands on it; ↓ takes
  you back down. It wraps in both directions, like the rest of the list.
- **It selects like a row**, so every command that works on a selected note now
  works on the note you are inside — copy, colour, task actions, move, delete —
  without a separate path for each one.
- **It stays put while you scroll**, so you never lose track of which note you
  are in.
- **It collapses to a single line once you scroll past it**, and shows the full
  preview again when you return to the top — so a long note does not eat the
  list you scrolled down to read.

Selecting the heading and selecting a note are still separate acts: it takes
the cursor on its own, and never joins a multi-selection alongside its own
children. A copy or a move covering both a note and its children at once is not
a coherent request, so it is not one you can accidentally make.

The separate one-line preview bar that used to appear on mobile is gone — the
pinned row does that job now, on both desktop and mobile.

## The home note is protected

Making the heading selectable made a folder's **home note** reachable by
commands that could never see it before. A folder whose home note has been
moved under another note, or deleted, is not a state Stashpad should be able to
reach — so both are now refused with an explanation, wherever the attempt comes
from: the menu, a drag, a keyboard shortcut, or the command palette.

## Smaller fixes in this release

- **Select mode no longer survives changing level.** Moving in or out of a note
  cleared the selection but left select mode switched on, so you arrived
  somewhere new in a mode with nothing selected and no obvious way out.
- The expand/collapse control on the heading is hidden while the heading is
  collapsed by scrolling — the collapse is not yours to undo at that point, and
  the button did nothing.
- Selecting the heading no longer scrolls the list back to the top.
