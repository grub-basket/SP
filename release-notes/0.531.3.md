# 0.531.3

This release covers every change since 0.530.5. Stashpad no longer greets people as new users before Obsidian has finished reading the vault. On a large vault, a network drive, or a coworker's first open of a shared vault, the "Welcome to Stashpad" setup dialog used to appear even though the vault already had Stashpads, one click away from creating new folders in it.

## First-run Welcome

- **0.531.0** — The Welcome dialog has always been skipped when the vault already contains a Stashpad. It made that decision 2.5 seconds after startup. On a vault Obsidian was still indexing, the existing Stashpads weren't visible yet, so the dialog appeared anyway. Stashpad now waits for Obsidian to finish its first index of the vault before deciding.
- **0.531.0** — Clicking the Stashpad icon (or running its open command) while Obsidian is still indexing shows "Obsidian is still indexing this vault — opening as soon as it's done" once, then opens your Stashpad, or the picker if there are several, as soon as indexing finishes.
- **0.531.0** — If the Welcome dialog opened on its own and a Stashpad turns up while it's on screen (a late index or a sync), it closes without creating anything and says which Stashpad it found. Opening the Welcome on purpose (Settings → Help & Getting started, or the command) works as before.
- **0.531.1** — The wait uses Obsidian's own "indexing complete" signal, the same one behind its "Indexing complete." notice. The first version keyed on a property Obsidian doesn't have and never actually waited. The wait gives up after 60 seconds so it can never hang. A dialog opened after that still steps aside if a Stashpad appears.
- **0.531.1** — The launch reminder about unsent drafts waits for indexing too, so an existing user on a slow first index no longer silently misses it.
- **0.531.3** — If Stashpad is updated or reloaded while Obsidian is indexing, the old copy can no longer open a second Welcome dialog.
- **0.531.3** — On a very slow index, one click on the Stashpad icon shows the "still indexing" notice once, not once a minute.

## Numeric-id sweep

- **0.531.2** — The one-time sweep from 0.528.2, which quotes all-digit note ids in frontmatter, was meant to wait until Obsidian had finished indexing and then two more minutes. It used the same missing property, so it simply started two minutes after launch. It now waits for indexing to finish, with no time limit, because it edits notes and must never run on a half-read vault.
