Mobile gets the bigger share of this release: the on-screen keyboard no longer dismisses and reappear every time you send a note, and several places where the list moved on its own now hold their position. Also new: a choice of where attachments are stored, a warning when an Obsidian setting Stashpad depends on is switched off, and "Open in Finder" in the folder panel.

## 0.214.3

- The folder picker in Encryption settings no longer runs its text underneath the dropdown chevron. The rule that enlarges that control was overwriting the space reserved for the arrow.

## 0.214.4

- That same picker now sizes itself to the folder name instead of a fixed width, growing leftward from the right edge and capping at the row. A longer folder name is no longer truncated early.

## 0.215.1

- **New: a warning when Obsidian's "Automatically update internal links" is turned off.** Stashpad renames a note's file when its first line changes, and with that setting off Obsidian will not repoint `[[wikilinks]]` to the renamed note, so links break silently as you edit. Shown once at startup, with a standing reminder in settings for as long as it stays off. Stashpad does not change the setting for you — it is a vault-wide Obsidian preference.
- **New: choose where attachments are stored.** Per-Stashpad `<folder>/_attachments` (unchanged default), one shared folder, or wherever Obsidian's own attachment setting points. Only affects attachments added from now on; existing files are never moved. The setting explains the trade-off: per-folder keeps a Stashpad self-contained but is what allows an attachment to be stranded when a note moves elsewhere.
- **New: "Open in Finder"** (or File Explorer, per platform) on folders and pinned notes in the folder panel. Desktop only.
- The folder-switcher button in its override state is now readable on any accent colour. It previously drew the accent as text on a neutral background, which washed out on a bright accent; the text colour is now chosen from the accent's brightness.

## 0.215.2

- `[color: fuchsia]` now resolves when importing text, matching the old desktop app's name for that palette slot.

## 0.216.0

- **The mobile keyboard no longer dismisses and reappears when you send a note.** The composer was rebuilt on every list render, which detached the focused text field — and detaching it is what dismisses the keyboard on iOS. The composer element now persists across renders and only the list and header around it are rebuilt. It is recreated only when something structural changes, such as switching folders.
- Side benefits: a re-render while you are typing no longer closes the autocomplete popover, and the Send button no longer steals focus from the composer when tapped.

## 0.216.1

- Sending a note used to trigger up to five full list renders in about a second and a half. Those renders are now coalesced into two, so the newly created note settles in place instead of repainting repeatedly.

## 0.216.2

- The mobile "jump to level" sheet lifts its content off the very bottom of the screen, clear of the home indicator, without leaving a gap beneath the sheet.
- Tapping a toolbar button no longer scrolls the list away from where you were. Dismissing the keyboard triggered a "keep the current row visible" scroll that fired even when that row was far off screen — after sending a note, that meant jumping back to the top.

## 0.216.3

- Toggling select mode no longer shifts the list. Select mode changes each row's appearance, so the scroll restore that follows a render landed at a slightly different offset each time.

## 0.216.4

- Changing a note's colour or marking a note as a to-do no longer scrolls the list. Same cause as the select toggle: these change a row's appearance in place, so the list should not move at all.
- When the list is scrolled to the bottom, these actions now keep it pinned there rather than settling backwards as note bodies finish rendering.
- Known issue: on some devices a smaller amount of movement remains in these cases. Under investigation.
