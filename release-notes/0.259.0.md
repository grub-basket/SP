# 0.259.0

## Fixed: "Copy focused subtree" now copies the focused subtree

The command has been called *Copy focused subtree* since it shipped, and its
settings description promised "the focused note + all descendants". It copied
neither — it copied whichever note happened to be **selected** in the list.

Because a row in the list is always selected, the code path meant to handle the
focused note could never actually run. So the command never once did what its
name said.

Both behaviours are worth having, so they are now two commands instead of one
name doing double duty:

- **Copy focused subtree** — the note you are currently *inside*, plus
  everything nested under it, no matter what is selected. This is what the
  command was always supposed to do.
- **Copy tree** — the note(s) you have **selected**, plus everything nested
  under them. Unchanged, and still on the same shortcut and in the ⚡ menu.
  Copying one child's subtree straight from a list is a genuinely useful thing
  and simply repointing the old command would have taken it away.

The settings description for *Copy tree* has been corrected to say what it
does, and to point at the other command for the focused case — the old wording
is what set the wrong expectation.
