# 0.291.1

Performance, batch 1: creating a note and saving an edit in a large folder are
much cheaper. Follows up on 0.290.0 (single-row repaint on edit).

Measured on a synthetic 400-note folder.

## Creating a note (0.291.0)

- **One list render per create instead of two.** After every create, a
  "settle" timer rebuilt the folder index and re-rendered the whole list a
  second time even when nothing had changed. The settle render now runs only if
  a render was actually suppressed during the window or the index really moved.
- **The plugin no longer re-renders for its own create event.** The vault's
  `create` event for a note the composer just wrote scheduled another full
  render on top of the direct one.
- **Index self-check is folder-scoped.** After every metadata resolve, each open
  Stashpad tab counted notes by walking the *entire vault* (with a metadata
  lookup per file). It now walks only its own folder's subtree, with the same
  reserved-subfolder exclusions, and hidden tabs defer the check until they are
  shown again instead of running it in the background.
- **Folder discovery is memoized.** The scan that finds every Stashpad folder in
  the vault used to run on every metadata resolve and up to nine times per
  settings render. It is now cached and only invalidated by events that can
  change the result (a file appearing in an unknown folder, a folder rename or
  delete, a frontmatter change that adds or removes a folder marker, the
  import-exclusion setting changing). Creates, edits, slug renames, sidecar
  files and author stubs inside known folders keep the cache warm.

## Saving from the edit modal (0.291.0, 0.291.1)

- **A body edit repaints just that row** — no folder-index rebuild, no full list
  render — unless the note's position can change (first line changed under a
  title sort, a filename re-slug, or a modified-time sort), in which case the
  list is re-rendered as before.
- **No more double work after Save.** The save's own file-modify event used to
  run the external-edit path on top: a second cache eviction, a *second*
  filename re-slug, and another repaint. The save now marks its write as its
  own, and the modify handler skips that work.
- 0.291.1: the self-write marker follows the note across a filename re-slug (only
  while unconsumed), so a modify event landing after the rename is not mistaken
  for an external edit.

## Notes

- Settings navigation is cheaper as a side effect of the discovery memo.
