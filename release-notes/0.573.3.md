# 0.573.3

This release covers every change since 0.567.0. The main change is to **drafts**: drafts of notes you had already sent stop coming back, and the Drafts window now shows which notes each draft matches, side by side, so you can clear them out.

## Highlights

- **Leftover drafts stop coming back.** When Obsidian syncs between devices, a draft deleted on one device (because you sent it or discarded it) now stays deleted. Before, another device could write its old copy back, so drafts of things you'd already sent kept reappearing.
- **Better duplicate matching.** Curly vs straight apostrophes, a checkbox added to the note, list markers, `#tags`, `~~strikethrough~~`, `==highlights==` and capital letters no longer stop a draft from matching the note it became. Edited or reworded drafts are flagged as similar too.
- **Compare a draft with its matches.** In the Drafts window, each draft's badge says **Already sent**, **Already in this note**, **Likely sent** or **N similar**. Click it to see each matching note with the words that differ marked, and **Open note** or **Discard draft** right there.
- **Discard all already-sent drafts at once.** A button at the top of the Drafts window lists the drafts whose whole text is already in a note and asks before discarding them.
- **Home and the breadcrumb return you to the note you came from**, instead of sometimes jumping to the bottom of the list.
- **Clicking a notification opens a new tab**, instead of replacing what the tab you were working in shows.
- **Windows-safe names** for every folder and file Stashpad names from a title, so vaults made on a Mac open on Windows.
- **Mobile:** swiping along the formatting toolbar no longer opens a sidebar.

## All changes

### 0.568.0–0.568.2, shipped as 0.571.0

- **0.568.0**: Home, or any higher breadcrumb, now lands on the note that leads back to where you were, not at the bottom of the list. This happened most after going into a note with the row's arrow, from search or from a link.
- **0.568.1**: A save that fails (for example on a network drive) is now recorded in the debug trace and the errors log, and saving an edit says when it failed.
- **0.568.2**: Fixes from review. Search and "reveal in context" land on their note again under the new Home rule, and a failed save is logged once, not twice.
- Changelog for this work added to the project's internal docs.
- **0.571.0**: The same work, renumbered above the versions merged in the meantime. No code change.

### 0.569.0

- Clicking a notification (a teammate's new note, "Jump to parent" after a move, a note sent to another folder, an adopted note) now opens its target in a new tab. If a tab already shows that exact note, that tab comes to the front. It never changes what an existing tab shows.
- All notification clicks go through one shared router, and a build check stops new notifications from opening tabs by hand.
- Internal developer docs updated to describe the new rule.

### 0.570.0

- One shared rule (`safeFileName`) for every file or folder name Stashpad builds from a title or typed name: splitting and renaming folders, Stashpad-app import folders, exports and encrypted files. Characters Windows can't use become dashes, quotes are removed, and reserved names (`CON`, `NUL`, …) and trailing dots are handled. Note filenames were already safe.
- Build: restored the notification check, which a merge had accidentally dropped from the build script.

### 0.572.0 and 0.572.1

- **0.572.0**: The Windows-safe filename patterns no longer need an `eslint-disable` comment; the matching itself is unchanged.
- **0.572.1** (mobile): Swiping sideways along the formatting toolbar in the composer, edit window or quick capture no longer opens the left or right sidebar.
- Internal docs: how to resolve version conflicts when merging, a cleanup of the developer notes, and the release-test steps.

### 0.573.0–0.573.3: drafts

- **0.573.0**: Drafts now merge one draft at a time when two devices change them. A draft only one side changed takes that side's version, a deletion included. If both edited it, the newer edit wins. If one side edited and the other deleted, the edit is kept, so typed text is never lost. Drafts still sync to, and can be opened on, every device.
- **0.573.1**: A shared text comparison for the "is this draft a leftover?" check. It ignores quote style, leading list, heading, quote and checkbox markers, `#tags`, inline formatting and case. Sending a note now also clears other drafts in that folder that match the start of what you sent.
- **0.573.2**: The Drafts window compares each draft with every note in its folder:
  - Match labels: **Already sent** (same text, or the draft is how the note starts), **Already in this note**, **Likely sent** (the note was created within seconds of the draft's last edit and shares its words), **Draft continues this note**, **Similar N%** and **Similar title**.
  - The badge is a keyboard-usable button that opens a comparison under the draft: underlined words are only in the note, struck-out words are only in the draft. Each match has **Open note** and **Discard draft**.
  - **Discard N already-sent drafts…** at the top, with a confirmation listing them. Only drafts whose whole text is in a note qualify, never "Likely" or "Similar" matches.
- **0.573.3**: Review fixes:
  - A draft re-saved unchanged by another device no longer counts as an edit, which could still bring a sent draft back.
  - Loading a draft again takes you back to the note you started it under, even after Obsidian reloads.
  - `#123`-style numbers are no longer treated as tags.
  - "Starts with" and "contains" now need whole words, so "Email Sam" doesn't match "Email Samantha…".
  - Discarding checks that the draft hasn't changed since it was compared.
  - The comparison is announced by screen readers.
  - Large folders use less memory.
- Internal changelog for the drafts work.
- Unit tests for the draft merge and the matching rules.
