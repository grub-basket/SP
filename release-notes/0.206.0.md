# 0.206.0

- **New: a per-folder recovery snapshot.** Stashpad now keeps a small
  `.stashpad-structure.json` beside your notes recording each note's id,
  parent, created date and path. If a note ever loses its frontmatter — a bad
  merge, an over-eager find-and-replace, a sync conflict — it becomes an
  anonymous orphan that Stashpad can't place. The snapshot is what puts it
  back.
- **New command: "Repair lost note frontmatter from the folder's structure
  snapshot".** It matches damaged notes by their file path (all that's left
  once the id is gone), restores id / parent / created, never touches bodies,
  leaves healthy notes completely alone, and is undoable.
- The snapshot is a photocopy, never the source of truth: if it's missing or
  stale nothing changes, because the tree is still built from frontmatter.
- It's written to survive the accident it exists for. An entry is only dropped
  when the note's **file is actually gone**; a note that disappears from the
  tree while its file is still on disk is treated as damaged rather than
  deleted and its position is kept. The previous snapshot is also rotated to
  `.prev.json` on each write.
- Cheaper than the per-note recovery links: one file per folder, written on a
  debounce, so a move that touches 50 notes costs one write instead of 50.
