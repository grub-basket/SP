# 0.483.0

Rolls up everything since 0.476.1. The bulk of it is a rework of deep links
(`obsidian://stashpad?…`): they no longer take over tabs you were using, they
survive Obsidian being closed when you click one, and they now tell you what
they did.

## 0.483.0 — Copy a link from where you already are

Stashpad could *open* a link from anywhere but could only *produce* one from a
note's context menu. Two new ways to get one:

- **The "Open Stashpad link" modal now offers the link for where you are** — a
  row under the paste field naming the note (or folder) you're currently in,
  with a **Copy** button. It's where the question "…and how do I get one of
  these?" occurs to you. The row is hidden when no Stashpad view is open.
- **Every breadcrumb crumb has "Copy Stashpad link"** in its right-click menu —
  for the crumb you clicked, not wherever the view happens to be focused. Each
  crumb is an ancestor, so this gives a link to any level of the path you're
  standing in without navigating there and back. **Home** copies a link to the
  folder itself (no note id): shorter, and it keeps working if the home note is
  renamed.

Both routes are recorded in **Recent links** (below) like any other copy.

## 0.482.x — Fixes and hardening for the above

- Re-clicking a link that already has a tab is logged as *reused*, not *opened* —
  and a link that pointed at an already-visible note reports "was already open"
  rather than claiming it opened something.
- The "can't open it" notice names what's actually missing. It used to say the
  *folder* wasn't in the vault when the folder was right there and only the note
  was missing — which is the commonest case, on a device that's still syncing.
- **Recent links** rows no longer clip: the per-row Open/Copy buttons sat past
  the edge of the panel, and the entry count stayed blank until you typed.
- A failure on one queued link no longer abandons the links queued behind it.
- **Clear log** keeps what it clears — the file is renamed aside rather than
  emptied, and if that fails, the log is left intact instead of being wiped.

## 0.482.0 — A link left on the clipboard gets opened at startup

Clicking a Stashpad link while Obsidian is closed can dispatch it before the
plugin exists to receive it; that link is simply gone, and nothing can see it.
The clipboard can be seen, though — copying is how these links travel.

So at startup, if the clipboard holds a Stashpad link for this vault that
nothing has acted on before, Stashpad opens it and says so, with a **Close it**
button in case it wasn't wanted. If the link can't be opened (a note that hasn't
synced yet), the notification offers **Try again** instead of discarding it.

It can't nag: each link is acted on **once, ever** — a link sitting on the
clipboard across ten restarts produces one tab — and it stands down entirely if
a link already opened this session or if the link is one you copied yourself.
Desktop only, and switchable off (Settings → Notifications → *Open a clipboard
link at startup*).

## 0.481.0 — Recent links

A new command, **Recent links (deep-link history)**, and a button in Settings →
Notifications. Every Stashpad link this vault has **copied**, **received**, or
**found on the clipboard**, newest first, with what became of each: opened,
revealed an already-open tab, reused its own tab, not found here, sent to
another vault, or never used. Filter by kind or by text; re-open or re-copy any
row.

The point is that a deep link's failure mode is silence. A link that reaches
Stashpad always leaves an entry — so an absence is itself the answer.

Kept **unlimited by default**, since the log's job is answering questions about
links sent weeks ago. A retention cap is editable both in the view and in
Settings, and the view shows the current entry count.

## 0.480.0 — Link receipts stay until dismissed

The confirmation a link opens with now stays on screen until dismissed, instead
of fading after a few seconds. It answers a question asked *later* — "did that
link actually work?" — and with *new tabs open in the background*, or the window
behind something else, a working link and a dropped one look identical. Settings
→ Notifications → *Link receipts stay until dismissed* turns it back into an
ordinary toast; the new **Links** notification category silences receipts
entirely.

## 0.479.0 — Deep links stop hijacking tabs, and survive a cold start

- **A deep link never changes what an existing tab is showing.** Previously only
  the tab in front was protected: a link would quietly re-point a *background*
  tab sitting on the same folder, moving it away from where you'd left it, out
  of sight. Now a link reuses the tab that link itself opened, or reveals a tab
  already showing its target without navigating it, or opens a new one.
- **Links survive Obsidian being closed.** The protocol handler was registered
  well into plugin startup, after several asynchronous steps. A link that
  cold-starts Obsidian is dispatched as soon as the app has a handler, and the
  app doesn't wait for plugins — so every one of those steps was a window in
  which the link vanished with no error anywhere. The handler is now claimed
  before anything else and queues the link until it can be served. A link that
  somehow still can't be served says so rather than disappearing.
- Opening a link now shows a receipt naming the note and folder it landed on,
  with a **Go to it** button, recorded in the notification history.

## 0.478.0 — Shift+Enter creates from what you typed

In Stashpad's search and picker modals, the **Create new: …** option only showed
up once nothing matched. **Shift+Enter** now creates from the current query text
even when there are matches, following Obsidian's quick-switcher convention.
Works in any picker that allows creation (search, move-to-note, fork, send
under…). Plain Enter still opens the highlighted result.

## 0.477.0 — Edit in the composer, bindable

**Edit note in the composer** is now a bindable command in Stashpad's own
keybinding settings — with no default chord, so nothing changes unless you
assign one. Its command-palette entry drops the "(experimental)" label.

## 0.476.2 — Four follow-ups

- The file preview's reading-width toggle now covers **images**, with their own
  separate state — stretching a photo no longer also widens your text previews.
  Images smaller than the reading column are untouched.
- The focused heading shows the **inherited** colour stripe when a note has no
  colour of its own, matching how list rows under a coloured ancestor already
  look.
- **Note text size** now also scales the note body in the detail panel and in
  the file-preview modal's note slide.
- The action-list settings builders (item buttons, star menu, context menu)
  support **drag-to-reorder**, alongside the existing up/down buttons.

## Also in this release

- **Kanban:** the refresh icon no longer collapses to zero width on mobile —
  Obsidian's tablet button padding squeezed the content box until the icon
  vanished, leaving an empty outline.
- Ten internal documentation and developer-tooling commits (handoff notes,
  parallel-testing notes, decision records) that ship no plugin change.
