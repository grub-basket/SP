# 0.416.0

Foundation for capturing **every** Stashpad toast in the persistent notification log. The `NotificationService` already recorded notifications, survived reloads, and had a viewer — but ~408 raw `new Notice(...)` calls bypassed it. Because those are bundled against a fixed `Notice` reference they can't be intercepted by patching, so they have to be routed through a function.

- `src/notify.ts`: `notify(message, opts?)` — a one-word shorthand that funnels each toast into the log via a sink installed on plugin load, falling back to a plain `Notice` before the sink exists so nothing is ever lost. Migration is now a trivial swap: `new Notice(x)` → `notify(x)`. Fragment-message and handle-returning Notices stay raw.
- `main.ts`: installs the sink (`setNotifySink`) right after settings load.
- First migration batch: `media-viewer.ts` (11 calls) and `detail-view.ts` (4 calls) routed through `notify`; unused `Notice` imports dropped.

Remaining raw calls migrate file-by-file in reviewed batches.
