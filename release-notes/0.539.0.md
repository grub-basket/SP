# 0.539.0

This release covers every change since 0.538.1. Obsidian's **New tab** screen now has an **Open Stashpad** button, next to **Create new note**, **Go to file** and the other built-in actions.

## Updates

- **0.539.0** — **Open Stashpad** on the New tab screen.
  - An empty tab shows Obsidian's list of actions. **Open Stashpad** now appears in that list, just above **Close**, styled like the built-in actions.
  - It opens Stashpad the same way as the ribbon icon:
    - no Stashpad yet: the Welcome screen
    - one Stashpad: opens it
    - several: the folder picker
  - Stashpad opens **in that empty tab**, the way **Create new note** does, instead of in another tab next to it.
  - If the Stashpad you picked is already open in another tab, that tab comes to the front and the empty tab closes, so there's no duplicate.
  - The button also appears on empty tabs restored when Obsidian starts, and on empty tabs in pop-out windows.
  - If you cancel the folder picker and move to another tab, a later Stashpad open won't take over the empty tab you left.

## Internal

- Obsidian has no API for the New tab action list and rebuilds it every time an empty tab opens. Stashpad re-checks empty tabs on layout changes and active-tab changes, and adds the row only where it's missing. The rows are removed when the plugin unloads.
- The clicked tab is passed to the existing open path through a one-shot target, `claimEmptyTabTarget`. It's used only while that tab is still empty and still the active tab. `activateViewForFolder` fills that tab instead of opening a new one. The two "already open" paths (`openFolderInStashpad` and the folder picker's reveal item) close the empty tab after focusing the open folder.
- A follow-up commit moved the new helper so the existing documentation comment on `activateViewForFolder` stays attached to it. Comment placement only, no behavior change.
- Merged the feature branch into main. Developer coordination notes don't ship in the plugin.
