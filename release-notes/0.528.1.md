# 0.528.1

This release covers every change from 0.516.0 to 0.528.1: many speed improvements, several data-safety fixes, and a new rule that Stashpad folders can't be placed inside each other.

## Data safety

- **0.516.0** — Deleting, locking or encrypt-deleting notes no longer permanently removes an attachment that isn't in the backup bundle. An image added to a note while the operation runs is kept and reported, not deleted.
- **0.520.0** — The `attachments:` property no longer gains an extra `]]` every time a note is deleted and restored, locked and unlocked, or pasted to another folder. Entries damaged by older versions repair themselves on their next round trip when the note's body still embeds the same file.
- **0.521.0** — When one Stashpad folder sat inside another, the inner folder's Home note could be treated as the outer folder's Home. The outer folder's child list was then written into it, and in some setups the inner Home was moved up a level. Each folder now uses only the Home note directly inside it.
- **0.523.8** — Restoring or unlocking notes keeps their attachments in the note's own folder. Previously they could be linked to an identical file in a different folder. Pasting from another vault now also writes its own attachment copy, which matches how cross-folder paste works.
- **0.526.5** — A folder no longer shows up completely blank when a note's id is all digits and the note shares its creation time with another note.
- **0.527.0** — Note ids made only of digits now work everywhere: manual order is saved, drag and drop onto them works, pinned notes show in the pin list, and deep links open them. The automatic orphan fix no longer gives such notes a new id, which used to detach their child notes. New ids always contain a letter. Once per device, a few seconds after startup, Stashpad puts quotes around existing all-digit `id:`/`parent:` values in Stashpad folders. The value itself never changes, and the run is recorded in the action log. After that, Rebootstrap does the same whenever you run it.
- **0.527.1** — Locking and automatic encryption include notes with all-digit ids. They were previously skipped, which left them readable. An existing `created` date stored as a plain number is never overwritten.

## Stashpad folders can't be inside each other

- **0.522.0** — A folder can't become a Stashpad when it sits inside an existing Stashpad, or when it would contain one. Existing Stashpads, including older nested ones, keep working. A tab pointed at a blocked folder shows "This folder can't be a Stashpad", with buttons to open the existing Stashpad or close the tab.
- **0.525.0** — The same rule covers folders Stashpad uses for its own files (`archive`, `trash`, `_attachments` and similar) in any capitalisation. A deep link refused by this rule is logged as "refused" and shows the reason. Startup does about a third of the checking it did in 0.522.0.
- **0.528.0** — Creating a new Stashpad inside another one now creates it at the top level of the vault instead (for example `Work/Ideas` becomes `Ideas`), with a notice saying where it went. If a top-level folder with that name already exists, Stashpad opens it instead. The folder switcher shows where a new Stashpad will be created before you choose it.

## Speed

- **0.517.0** — With the detail panel open, moving between notes no longer rebuilds a vault-wide autocomplete list each time.
- **0.517.1** — Typing in the Edit window on long notes is much faster: about 47 ms per key dropped to about 12 ms in testing.
- **0.517.2** — Fewer disk operations at startup (trace-file cleanup and author registry loading).
- **0.517.3** — Switching a tab to another folder shows the new folder straight away instead of waiting for the workspace layout to save.
- **0.517.4** — Obsidian startup on large vaults no longer re-runs Stashpad folder discovery for every file it loads.
- **0.517.5** — The Folder panel redraws about four times faster.
- **0.517.6** — The list filters (Hide completed and similar) update the list immediately instead of after the settings file is saved.
- **0.517.7** — Undo of a delete, Trash restore and unlock request note reads in batches. There's little gain on desktop, where Obsidian reads files one at a time.
- **0.517.9** — Copying, cutting or pasting several notes, and OKF export, read the folder once instead of once per note.
- **0.518.0** — The hide-on-a-schedule check reuses its date formatters, so list redraws are about 18% faster when it's on.
- **0.518.1** — Date formatting in rows and panels reuses cached formatters.
- **0.518.2** — Bulk delete or lock saves the render cache in fewer writes.
- **0.518.3 / 0.518.4 / 0.518.5** — The note picker does less work per keystroke. It's about 2–3× faster in large vaults.
- **0.518.6** — The Panels view's Pinned panel scans the vault twice per redraw instead of up to 29 times.
- **0.518.7** — Sorting by title is about 4× faster.
- **0.518.8** — The All notes, Task timeline and Due calendar tabs ignore edits to notes outside Stashpad folders. Side effect: a note that becomes a Stashpad note through an outside edit appears in those tabs after the next relevant change or a Refresh.
- **0.519.0** — The Edit window's line-number gutter measures all lines in one pass: about 35 ms per key dropped to about 5 ms on a 320-line note.
- **0.519.1** — Undo or redo of a cross-folder paste checks each folder once.
- **0.519.2** — Dropping or pasting many files checks the attachment folder once.
- **0.519.3** — A bulk delete with several Stashpad tabs open rebuilds each tab's list once instead of once per note.
- **0.519.5** — Editing ordinary (non-Stashpad) notes no longer makes Stashpad rescan its folders. This also fixes a synced change to the excluded-folder setting not refreshing the folder list.
- **0.519.6** — Task checkboxes redraw only when their done state changes.
- **0.519.7** — Each row works out its hidden, pinned and task state once.
- **0.519.8** — Table and callout chips no longer force a layout pass on every redraw.
- **0.524.0** — Filtered lists (for example Hide completed with a search) no longer scan the whole vault for every row. Each filtered redraw went from roughly 60–170 ms to about 1 ms on a large test vault.
- **0.524.1** — The Folder panel and the Panels view don't redraw while hidden behind another sidebar tab. They refresh as soon as they're shown.

## Other fixes

- **0.523.1** — Redo of a prepend or append works again when the prepend renamed the note.
- **0.523.2** — Opening a folder repairs a stale `parentLink` on top-level notes. Only links that are wrong get rewritten.
- **0.523.3** — Home notes no longer get a `parent: __root__` property added to them.
- **0.523.4** — Rebootstrap and the open view write child lists in the same order, so they no longer rewrite each other.
- **0.523.5** — A duplicate "Locked" section no longer appears after quick re-renders.
- **0.523.7** — A parent task's "N of M subtasks done" count updates when a subtask is changed on another device.
- **0.523.9** — Stashpad's own moves, pins, swaps and undo/redo are no longer recorded as "Edited outside Stashpad" in the activity log.
- **0.526.1** — Choosing Sort → Manual sticks, even after another sort order was saved.
- **0.526.2** — The delete notice counts every note removed, including the notes below the one you selected.
- **0.526.3** — Search previews keep the matched words visible.
- **0.526.4** — No flood of "X added a note" notices when a folder newly becomes visible to Stashpad.
- **0.528.1** — Removes a leftover console message.
- Code comments describing measured gains were corrected (no behaviour change).
