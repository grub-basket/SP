# 0.294.0

Performance, batches 3 and 4: creating a note no longer re-renders the list at
all in the common case, edited notes re-cache immediately, and startup no
longer waits on the render cache or the encryption-key scan.

## Creating a note (0.294.0)

- **Creating a note appends one row instead of rebuilding the list.** When the
  new note lands at the end of the current view (the usual case — newest-last,
  manual, or flat order), only its row is built; the existing rows are left
  untouched. Mid-list inserts (newest-first or title sorts, filters that move
  rows, folders with locked placeholders or loose files interleaved) still do
  the full render.
- **Recovery-link writes are coalesced.** The parent's `children` link list is
  computed once per write (it was computed twice), and the sync queue now
  drains children before their parent, so a burst of creates under one parent
  rewrites that parent's frontmatter once instead of once per note.

## Editing (0.293.0)

- **Edited notes re-cache immediately.** The render cache placed a 60-second
  "tombstone" on a note after *any* eviction — originally a safeguard so a
  locked or securely deleted note's plaintext could never be re-admitted — which
  also meant an ordinarily edited note was re-rendered from markdown on every
  paint for a minute. The tombstone now applies only to the delete/lock path;
  normal edits re-cache on the next render. Cached bodies are validated against
  the file's modification time on read, so this does not weaken staleness
  checks.

## Rendering (0.293.0)

- **Flat and "everything" views no longer scan the vault once per row.** The
  locked-subtree lookup walked every file in the vault for each rendered note;
  it now builds one index per render.
- **Pin-to-bottom after sending no longer attaches a resize observer to every
  row.** The existing per-frame watchdog already covered it.
- **Stylesheet:** rows use CSS containment (`contain: layout style`) so a style
  or layout change in one row doesn't walk all of them; the row hover no longer
  animates `box-shadow` or applies a `filter` (a selected row's hover uses a
  blended background instead); on mobile, the "no animations" rule is scoped to
  the elements that actually animate instead of every node in every row.

## Composer (0.294.0)

- **Similar-notes search is cheaper while typing.** Note titles are memoized
  (keyed on path + modification time), the result sort no longer re-derives
  titles per comparison, and the search runs once after you pause (350 ms)
  rather than three times a second mid-word.
- The per-folder structure snapshot (a recovery sidecar) is now built when its
  debounced write fires, not on every metadata event.

## Drag and drop (0.294.0)

- Dragging over a long list no longer measures every row on every mouse move.
  Row geometry is cached at drag start (in list coordinates, so scrolling
  doesn't invalidate it), looked up by binary search, and processed at most
  once per animation frame. Drop zones — above / into / below — use the same
  thresholds as before.

## Startup (0.294.0)

- **The render cache loads in the background.** Plugin load no longer waits for
  the whole persisted cache (up to 4000 rendered bodies) to deserialize; the
  first body render waits for it instead, and entries written before the load
  finishes are never overwritten by it. The stale-entry sweep runs a few seconds
  after layout is ready rather than on the load path.
- **Encryption-key discovery is off the load path** and walks folders eight at
  a time instead of one after another. Anything that needs the keys (unlocking,
  the encryption commands, archive-on-move checks) waits for the index to be
  complete rather than reading an empty one. If a folder is registered as
  locked, the scan starts immediately as before.
