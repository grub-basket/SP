# 0.200.0

Performance round for slow / network-drive vaults (levers L1–L3 from the perf
playbook):

- **The render cache now lives in IndexedDB — on the local machine — instead of
  a JSON file inside the plugin folder.** When a vault sits on a network share,
  the old cache file did too, so loading and saving the cache itself paid
  network latency. Cache I/O is now always local. An existing
  `render-cache.json` migrates automatically on first load and is then removed
  (it holds note text, so a stale copy must not linger — this also covers a
  sync tool restoring an old copy later). If IndexedDB is unavailable the old
  vault-file storage is used as a fallback.
- **The cache is LRU-bounded (4000 entries).** Least-recently-viewed rows are
  dropped on save instead of the cache growing toward vault size; a dropped
  row simply lazy-renders again if ever scrolled to.
- **Verified cold visible rows read in parallel** — a screenful of uncached
  rows costs roughly one network round-trip, not one per row. (No code change
  needed; confirmed by measurement.)
