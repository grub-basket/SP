# 0.319.4

Everything since 0.316.8: making an existing note a reply, a review pass on the
old scroll band-aids, search ranking across folders, three mobile fixes, the
reaction picker's new sections, id-keyed composer drafts with a review modal,
an experimental edit-in-composer flow, natural-language dates for `@` and the
search filters, and a handful of settings and design touches. Grouped by
version; one bullet per change.

## 0.317.0 — Make an existing note a reply

- **Context menu (desktop right-click and mobile long-press): "Make a reply
  to…"** opens the note picker (this folder plus other Stashpads) and writes the
  same `replyTo` / `replyToBlurb` frontmatter the composer stamps on a new reply,
  so the row's "Reply to" quote and jump-to-source behave identically. **"Remove
  reply link"** appears when the note already is a reply. A note cannot be made a
  reply to itself.
- **Command: "Make note a reply to…"** for the cursor / selected note.
- **Edit surface chip.** The edit modal and the popped-out workbench tab show a
  "Reply to …" chip above the editor with Change / Remove (or "Make a reply…").
- Every change is one undo entry (undo / redo resolve the note id-first, so a
  re-slugged file still restores) and is logged as a new `reply_link` action
  (Log panel + activity heatmap, bucketed under "edited").
- Docs: a TODO entry records the editing-model decision (composer-edit vs
  in-place vs modal) and the interim reply-link route.

## 0.317.1 — Reply chip gated on Save; reply picker order

- **The edit-surface reply chip no longer writes immediately.** Picking or
  removing a target is a *pending* change: the surface counts as dirty (Cancel /
  Esc / closing the tab prompts to discard), a "Revert" button drops it, and
  Save writes the body first and the reply link only when the body save was
  not refused. The pending change travels with the pop-out. `performEdit`
  now reports whether the save was refused.
- **"Make a reply to…" lists the current folder newest → oldest by created
  date** and does not float the home note (`StashpadSuggest` gained
  `recency: "created"` and `pinHomes: false`).
- Docs: the session handoff uses a placeholder home path; the backlog records
  the queued reaction-UI asks and the on-device confirmation of the 0.316.8
  root fix.

## 0.317.2 — Scroll band-aid review

- With the 0.316.8 root fix confirmed on-device, the R1-era helpers were
  re-evaluated. **Removed:** the duplicated `|| stickToListBottom` predicate in
  the legacy and `preserve` re-pin branches — `prevAtBottom` already folds the
  flag in at its definition, so the extra test was dead. **Kept on purpose:**
  hide-until-settled, the settle loop's two-tick stable streak and the scroll
  pin token (they hide the empty → partial → full paint of a fresh open, which
  is real content arrival, not the estimate bug). The `r1:settle` trace's
  `lastIdx` now reads the last rendered row (it always read `null` in a
  virtualized list). The seven-check virtualization battery is identical before
  and after.

## 0.317.3 — Search ranking across folders

- **Cross-folder notes get real titles** in the search modal: the first heading
  or first body line (as local notes always had), no longer a de-slugged
  filename — so an exact-title query can reach the top band. A slug-derived
  title is upgraded to the real first line once the picker lazy-reads the body.
- **With a query, local and cross-folder hits rank together** by relevance
  band, the current folder winning ties, then recency — instead of every local
  hit (even a weak body match) sitting above every other folder's hit. Pick
  mode (Move / reply destinations) keeps local-first tiers; an empty search
  keeps the local cap and the cross-folder section.

## 0.317.4 — Mobile: folder panel taps, composer caret

- **Folder panel: tap vs scroll.** Touch and pen now open a folder on a *still*
  `pointerup` (≤ 10 px of movement); a scroll gesture ends with `pointercancel`
  and disarms. Acting on `pointerdown` had made every touch a tap, so a scroll
  that began on a row opened that folder. Mouse keeps the pointerdown path.
- **Composer caret over the drawer.** The composer is blurred on *any* drawer
  motion — a style-attribute observer on both mobile drawer containers fires on
  the first frame of an open, whether it came from an edge swipe, a swipe that
  started inside the content, or the navbar buttons. The earlier edge-gutter
  heuristic stays.

## 0.318.0 — Reaction picker sections, chip height, mobile chips row

- **Bundled emoji dataset** (`src/emoji-data.ts`, generated once from
  emojibase-data 17.0.0, MIT): 1914 base glyphs with labels, groups and tags;
  no runtime dependency.
- **Search over the full set** — labels, tags and the GitHub/Slack shortcodes,
  merged per glyph. Tiers: exact name → name prefix → name substring → exact
  tag → tag prefix (so "rock" lists 🪨 and 🚀 before the singer tagged "rock").
- **Sections:** search on top · **Favorites** (pinned in settings, synced;
  shows the 8 presets until any are pinned; an **Edit** mode where tapping any
  emoji pins or unpins it, ★ badge) · **Recent** (per device, capped at 24,
  rebuilt after every pick) · **All** (nine groups with headers and a tab strip
  that scrolls to each; the ~1900 buttons are built on the next tick so the
  sheet paints immediately).
- **Multi-pick:** a tap toggles the reaction and the picker stays open; buttons
  reflect your current reactions; a footer "Done" closes (Esc / outside click
  still work on desktop).
- **Reaction chip height:** `button.stashpad-reaction-chip` is pinned to the
  action buttons' 22 px box on every platform (Obsidian's mobile `<button>`
  padding and min-height had made it 44 px).
- **Mobile chips row at the bottom of the note:** a new full-width grid row
  under the body, wrapping as it fills; the picker button stays on the top row
  with its siblings. Mobile shows every reaction (no top-3 cap); desktop keeps
  the meta-column cap and the "+N" overflow.
- Settings key `favoriteReactions`.

## 0.318.1 — Folder panel: first swipe cut short

- The first touch on an unfocused sidebar makes it the active leaf, which
  scheduled a full rebuild of the folder panel 100 ms later — under the finger,
  killing the scroll and zeroing both lists. A scheduled rebuild now waits while
  a non-mouse pointer is down or a scroll happened in the last 300 ms, and every
  rebuild saves and restores the scroll offset of the pinned and folder lists.

## 0.319.0 — Composer drafts by id; edit-in-composer; natural-language dates

- **Drafts are keyed by draft id, not folder** (`settings.composerDrafts`, new
  `ComposerDraft` type: folder, text, created, modified, device label, kind).
  Several drafts per folder are allowed — other devices' via sync, stashed
  text, an edit in progress. The existing key-level union merge means two
  devices writing their own ids never clobber each other. Legacy per-folder
  strings migrate as `legacy:<folder>` entries on load and the legacy map is
  cleared.
- **Per-device binding:** each view binds one draft per folder (remembered in
  local storage), adopting the newest plain draft when unbound. A bound draft
  deleted elsewhere unbinds without wiping live typing.
- **The reply target now travels with the draft** (it used to be lost on
  reload).
- **Drafts chip + modal:** an "N drafts" chip in the composer when the folder
  holds more than the bound one opens a modal listing drafts (Load into
  composer / Copy / Delete; grouped by folder when opened for all). Also:
  command "Show composer drafts" and a settings row.
- **Edit-in-composer provision (command-only):** "Edit note in the composer
  (experimental)" flushes the current text as its own draft, binds an *edit*
  draft holding the note's body and a markdown snapshot, and shows an
  "Editing: <title> ✕" chip. Send saves through **`writeEditedBody`** — the edit
  modal's save lifted out of `cmdSplit` so the modal, the popped-out tab and the
  composer share one chokepoint (divergence prompt, self-write markers, reslug,
  log, undo) — then applies a pending reply target (R on another note while
  editing) and rebinds to the folder's next draft.
- **Natural-language dates** (`src/natural-date.ts`, dependency-free, DST-safe
  calendar math) back both the composer `@` trigger (prefers the future) and
  the search filters `before:` / `after:` / `on:` (prefer the past, as before).
  Understood: today / tomorrow / yesterday / tonight; weekdays with next, last,
  this, coming; next/last week, month, year; end or start of week, month, year;
  "in 3 weeks", "2 days ago", "3 weeks from now", "in 45 min"; 7d / 2w
  shorthand; ISO and US dates; month names either order with ordinals; times
  (3pm, 15:00, "at 3", noon, midnight, morning / afternoon / evening). The `@`
  catalogue is generated (weekdays relative to today, next/last <weekday>, …)
  and every phrase resolves through the parser; the Natural Language Dates
  plugin is still asked first when installed.

## 0.319.1 — Loss-proof cancel; edit-surface routing; date rules

- **Stopping an edit keeps your changes.** ✕ on the editing chip (or the cancel
  command) keeps a *changed* edit in the drafts list as an edit draft ("Resume
  editing" in the modal) and only drops an untouched one; either way the
  composer rebinds to what it held before. Edit drafts are never adopted
  implicitly, so a stopped edit cannot hijack the composer.
- **Edit-surface routing by note length, per platform** (`settings.editRouting`):
  composer (opt-in toggle, off by default) → edit modal → workbench tab →
  Obsidian's editor. Defaults desktop 500 / 8000 / 60000 characters, mobile
  250 / 3000 / 20000. Settings → Composer: the toggle "Edit short notes in the
  composer (experimental)" plus a limits row per platform. `cmdSplit` gained a
  `host: "modal" | "tab"` parameter so long notes open straight in the tab.
- **Dates:** a month-day without a year is always *this* year (no next-year
  bump). Suffixes "next year" / "of next year" / "last year" on any month-day
  form. Ordinal weekday-of-month: "third tuesday of june", "last thursday of
  next month", "2nd friday in march 2027", "first monday of feb at 9am",
  "last friday of the month"; a non-existent fifth weekday resolves to nothing.
- Regression fixed in the same version: "next month" parsed as Monday — weekday
  forms are now explicit (mon / monday / tue / tues / …).

## 0.319.2 — Drafts modal design

- Each draft is a card: an accent stripe and an "Editing: <title>" badge for an
  edit in progress, one quiet meta line ("This device · edited a few seconds
  ago", "started …" only when it differs, "reply to …" when set), a four-line
  clamped preview, and the primary action full-width on mobile with Copy and
  Delete beneath. Edit drafts say "Resume editing".

## 0.319.3 — Chip close buttons

- The ✕ on the reply chip and the editing chip is a square 22 px icon button
  (lucide `x`, 14 px stroke, rounded, with a hover fill and outline) instead of
  a bare text glyph; both carry an `aria-label`.

## 0.319.4 — Settings polish

- **Edit surface limits:** the description is one line per tier and each of
  the three boxes is labelled (composer / modal / tab) with matching placeholder
  text.
- **Blur schedule:** the "Blur only during set hours" toggle now leads its
  explanation instead of following it.
- Docs: handoff and backlog record the `composer-drafts` merge.
