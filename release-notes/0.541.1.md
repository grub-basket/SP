# 0.541.1

This release covers every change since 0.541.0. A Stashpad folder that is deleted, moved or renamed outside Stashpad now stays where it went. Open tabs follow it instead of closing, and Stashpad no longer brings back an empty folder under the old name.

## Updates

- **0.541.1** — Folders that vanish stay gone.
  - **Open tabs stay open.** When a Stashpad folder is deleted, moved or renamed outside Stashpad (in the file explorer, on another computer on a shared drive, or through sync), its tabs used to close straight away. A rename made on another computer looks exactly like a delete, so the tab never got the chance to follow it. Tabs now stay open on the **This folder was moved, renamed or deleted** page, and follow the folder when it turns up under its new name.
  - The **was deleted** notice now waits a few seconds and is skipped if a tab followed the folder. When it does appear, it says the folder was deleted, or moved or renamed outside Stashpad.
  - **Empty folders left at the old name.** Stashpad now remembers moves it has seen. If an empty folder appears at a folder's old name, for example recreated by an older version of Stashpad on a coworker's computer, a tab opening it shows **This folder's notes moved somewhere else** and offers the real location. It doesn't quietly set the empty folder up as a new Stashpad. **Make this a new Stashpad** is there if you really do want a fresh one at that name. Creating a new Stashpad from the folder switcher is unaffected.
  - **Nothing in the background recreates a missing folder.** Note history only creates its own `.stashpad` folder inside a Stashpad that still exists. The hidden structure, order and sort files, the OKF `index.md`, and the startup migration of older encryption key files all check that the folder is still there first.
  - **Structure backup fix.** Switching a tab to another folder within about 4 seconds of a change could save the new folder's notes into the old folder's hidden structure backup (`.stashpad-structure.json`). That no longer happens.
  - **Coworkers on a shared drive should update too.** An older Stashpad on another computer with a tab open on the old folder can still recreate it there.

## Internal

- `handleStashpadFolderDeleted` no longer calls `closeStashpadTabsFor`. Stashpad's own **delete with undo** still closes tabs as before.
- New per-device move record (`recordFolderMove` / `readFolderMoves` / `forgetFolderMove`, capped at 200 entries). It is used first by `findMovedFolder` and by `isKnownStashpadFolder`.
- New `plugin.allowRecreate`. The missing-folder page has a separate mode for an empty folder left at the old name, and that mode never follows automatically.
- `NoteHistoryStore.mkdirp` refuses to create folders above `.stashpad`. The structure, order and sort stores only check the folder when their own file is missing, so normal writes cost nothing extra.
- Developer changelog notes for the branch. They don't ship in the plugin.
