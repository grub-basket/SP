# 0.574.0

This release covers every change since 0.573.3. The note edit window now saves when you press **Enter**, the same way the composer sends. **Shift+Enter** adds a new line. A setting switches back to the previous keys.

## Highlights

- **Enter saves in the edit window.** Press Enter (Return) to save the note you're editing. Press Shift+Enter for a new line. ⌘/Ctrl+Enter still saves too.
- **New setting: "Enter adds a new line when editing a note"** (Settings → Behavior → Composer & Editing). Turn it on and Enter adds a new line again, and you save with ⌘/Ctrl+Enter or the Save button.
- **On a phone, a new Return button sits next to Save.** Phone keyboards can't type Shift+Enter, so tap this button to make Return add new lines in that window, and tap it again to make Return save. It only affects the window you're in. Your setting doesn't change, and your cursor stays where it was.
- Split mode hasn't changed. Enter still adds a new line there.

## All changes

### 0.574.0

- The edit window (the edit modal and an edit window popped out into a tab, on desktop and mobile) saves on a plain Enter. Shift+Enter adds a new line, and list continuation now runs on Shift+Enter, so a new `- ` bullet still follows a list item. ⌘/Ctrl+Enter saves the same as before.
- Some Enter presses do something else first, so they don't save:
  - picking a suggestion from the `#` / `[[` / `@` autocomplete list
  - adding a row in a Markdown table
  - confirming text in an input method (IME)
- Holding Enter down saves only once. The repeats are ignored, so when you edit several notes in a row, a held key can't also save the next note.
- New setting `editEnterNewline`, labelled "Enter adds a new line when editing a note", under Behavior → Composer & Editing. It's off by default. With it on, Enter adds a new line, Shift+Enter does too, and ⌘/Ctrl+Enter saves.
- The help line under the editor and a new hint on the Save button show the current keys: "Save (↵)", or "Save (⌘↵)" / "Save (Ctrl+↵)" when the setting is on. The hint stays hidden on mobile, like Cancel's "(Esc)".
- Mobile: a Return-mode button next to Save, using the same icons as the composer's Enter button. It switches what Return does for that window only. It updates in place, so your cursor position, selection, scroll position and undo history are kept.
- Split mode is unchanged.
