# 0.292.0

Performance, batch 2: settings and tab changes no longer re-render every open
Stashpad tab, and typing in the composer no longer hammers `data.json`.

## Settings changes stop fanning out (0.292.0)

- **Switching between Stashpad tabs no longer re-renders all of them.** Every
  leaf change wrote the "recent folders" / "last used folder" bookkeeping with a
  full settings save, which broadcast to every open Stashpad tab and made each
  one rebuild its list. That bookkeeping is now written quietly (no broadcast)
  and debounced to one write per burst of switching; it is flushed on quit.
- **Per-folder filter toggles only repaint the tabs that show that folder.**
  Hide-completed, hide-childless, attachments-only, the encryption filter, the
  "everything" attachments toggle and the view mode are no longer part of the
  global "does this need a re-render" signature. The tab that changed the
  setting repaints itself as before, and other tabs on the *same* folder follow;
  tabs on other folders are left alone.
- A filter change that arrives from **another device via sync** still repaints
  the affected tabs (forced only for those keys, not for bookkeeping changes).
- The render signature itself is cheaper: the key list is cached instead of
  being re-sorted on every save.

## Composer typing (0.292.0)

- **Draft autosave waits for a pause.** It used to fire every 250 ms while you
  typed — each time re-reading and re-diffing the whole settings file and
  writing it back (roughly four times a second). It now saves once, about
  800 ms after you stop typing, and still saves immediately on blur, submit,
  tab close and quit. A pending autosave is cancelled on submit so it cannot
  resurrect a sent draft.
- **Settings writes do a third of the comparisons.** The multi-writer collision
  guard stringified every key three times per write; the strings are now
  computed once per write and reused. The guard itself is unchanged.

## Render cache (0.292.0)

- **Editing a note no longer serializes the whole render cache.** Evicting one
  note's cached body used to write the entire cache (up to 4000 entries of body
  text plus rendered HTML) to IndexedDB immediately — on every external or
  synced edit, and on every editor autosave of a note open in a normal pane.
  Persistence is now debounced like a normal cache write. Deleting a file
  (which is how locking and secure-delete purge plaintext) still flushes
  immediately.
