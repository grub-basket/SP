# 0.277.2

Companion sidecar encryption, a one-click Encrypt-all button, a sweep that cleans
up companions left plaintext by earlier locks, and a setting to choose which
companion file types are protected.

## Companion sidecars are now encrypted with their notes

Encryption locks a note's file on disk, but other plugins keep their own
plaintext files next to a note — most notably the Edit History plugin's `.edtz`,
which holds the note's full edit history. Until now, encrypting a note left that
sidecar readable on disk, so the note's history stayed exposed.

Now those companion files ride **inside** the encrypted bundle:

- A new setting, **Companion file extensions to encrypt** (`encryptCompanionExts`,
  default `.edtz`), lists the sidecar extensions to protect. For each note being
  encrypted, Stashpad finds its matching `<note><ext>` companions in the same
  folder, packs them into the same encrypted `.stashenc` blob, and removes the
  plaintext copies.
- **Unlocking restores them** next to the note, byte-for-byte, under the note's
  filename — so the Edit History plugin re-pairs with its history automatically.
- This applies on **every** lock path: locking a note or a whole folder,
  encrypting an archive folder, and secure-deleting to encrypted trash. Companions
  also travel into the plaintext trash on a normal delete, so a deleted note no
  longer strands its sidecar.
- The safety guarantees are unchanged: the encrypted copy is written and verified
  before any plaintext is removed, and a companion changed mid-operation is kept
  (never destroyed) and reported.

## Encrypt everything now — one click

A new **"Encrypt everything now"** button in the Encryption settings (and a
matching **Encrypt everything now** command) locks, in a single pass, everything
that should be encrypted but is currently plaintext: notes you've unlocked or
restored, and any folder set to encrypt its notes or its archive.

- You **confirm first** — the dialog names exactly what it will sweep, notes that
  companion sidecars ride along, and suggests pausing any sync/cloud service for a
  large run.
- While it runs, a **blocking overlay freezes the Stashpad UI** so nothing is
  edited mid-encryption. When it finishes, it reports what was locked.
- Writes are done safely (each note's encrypted copy is verified before its
  plaintext is removed), and Stashpad does not touch Obsidian's sync internals.

The existing deselectable "re-encrypt sweep" review is still available; the new
button is the run-it-all shortcut.

## Cleaning up companions from earlier locks

Companions are only protected from the moment this feature exists — a note that
was locked **before** it shipped still had its plaintext sidecar (e.g. `.edtz`)
sitting on disk. The sweep now finds and re-protects those too:

- It scans your encrypted folders for a companion file whose note is no longer
  present as plaintext (its note was locked earlier), and reports the count in the
  confirmation before doing anything.
- Where the note is still recoverable, the companion is **folded back into that
  note's encrypted bundle**, so unlocking the note restores its history alongside
  it, exactly as if it had been encrypted together in the first place.
- Where the note is gone entirely, the companion is **encrypted on its own** (and
  restorable via "Decrypt a folder bundle…") rather than deleted or left readable.

This runs as part of the same Encrypt-all button, review sweep, and command.

## Choosing which companion files to protect

The Encryption settings gain a **Companion files to encrypt** field. It lists the
sidecar extensions (default `.edtz`, for the Edit History plugin) that get locked
inside a note's bundle — add others (comma-separated) if you use a different
history or annotation plugin, or clear it to protect none. Entries are normalized
to a leading dot; `.md` is rejected, since a companion is matched by the note's
own name and `.md` would point back at the note itself.

## Groundwork and documentation (0.276.10 – 0.276.11)

- Added the `encryptCompanionExts` setting as the foundation for the companion
  encryption above.
- The README and Encryption settings are now explicit that encryption is **not** a
  decrypted-in-RAM-only model: while a note is plaintext (before locking, or after
  unlocking), other software may keep plaintext copies Stashpad cannot reach —
  Obsidian's File Recovery snapshots and Sync version history, other plugins'
  sidecar files, and OS backups. Encryption protects a locked note going forward;
  it does not retroactively purge traces that already existed.
