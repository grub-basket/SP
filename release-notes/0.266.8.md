# 0.266.8

Link previews grew an automatic mode and learned to fold properly, the pinned
heading stopped fighting the scroll, and a long-running render bug that made
the list flicker on mobile was finally traced to its cause.

## Link previews

### 0.265.0 — expanded by default, and an automatic mode

Previews now render **expanded**. Shipping them collapsed hid the description,
which is the entire point of capturing it: a callout authored collapsed renders
its content with `display: none`, so the text was there and invisible on every
platform. Collapsing is now opt-in via a setting.

A new **automatic mode** adds previews to notes as you save links, rather than
waiting for an explicit command. Off by default — it makes network requests on
your behalf, so it should be a decision rather than a surprise. It skips notes
it has just written itself, so its own output never triggers another round.

### 0.265.1 — folding works inside Stashpad

Folding a callout in a Stashpad list did nothing, while the same callout folded
correctly in Obsidian's editor. Two causes, both from note bodies being restored
from cached HTML: the cache reproduces the fold chevron's markup but not the
click handler Obsidian attaches when it renders a callout live, and Obsidian's
collapse CSS is scoped to its own preview container, which Stashpad does not
render into. Both are now supplied.

### 0.265.2 — fold on the chevron only

Folding on the whole callout title collided with double-click-to-enter-a-note: a
double click folded, unfolded, and navigated, which reads as a flicker. Folding
is now restricted to the chevron, whose hit area is enlarged so it stays tappable
on a phone. Restricting the target removes the conflict outright rather than
arbitrating it with a timer, which would have delayed every fold to serve the
rarer gesture.

### 0.266.2 — expanding a collapsed callout reveals its description

Expanding a preview rotated the chevron and left the body hidden — the title
expanded and the description did not. Obsidian's renderer writes an **inline**
`display: none` onto the content of a callout authored collapsed, and an inline
style outranks any stylesheet, so toggling the class alone could never reveal it.
Only callouts authored collapsed carry that inline style, which is why previews
written before 0.265.0 were affected and newer ones were not.

### 0.266.4 — folds survive a re-render

Note bodies are rebuilt from cached HTML, which carries the state the note was
*authored* in, so expanding a preview and then getting any re-render snapped it
shut again. The state you choose is now remembered per note and re-applied.

Callouts are identified by position **and** title, so editing above one, or
holding two previews of the same page in a single note, falls back to the
authored state rather than folding the wrong one. The state is kept in memory
rather than written to the note: this is "what I am looking at right now", not a
document property, and persisting it would mean a file write per fold.

## The list stopped flickering

### 0.266.6 — a slow trickle is no longer mistaken for a render storm

Stashpad stretches its render debounce during a burst of file changes so the
list settles once instead of thrashing. The detector kept a running count plus a
sticky flag, reset only when the gap between two *consecutive* changes exceeded
the calm window — which means "reset only if no two changes are ever close
together", so any steady trickle held the stretched delay indefinitely. Because
that delay is shorter than the calm window, a trickle at roughly its own cadence
could never clear it, and the list re-rendered on a fixed metronome for as long
as anything kept touching files.

It is now a **rate** measured over a moving window, recomputed each time, so it
cannot latch: when changes thin out, the old ones age out. A genuine burst is
still detected and still coalesced.

### 0.266.3 — the pinned heading stops oscillating

The collapsed state of the pinned heading is measured from a scroll position that
the collapse itself changes: collapsing shortens the content, which on a short
note removes the overflow and snaps the scroll to the top, which reads as "not
collapsed", which expands it again. The heading now uses two thresholds —
collapsing takes a decisive scroll, expanding takes a return to the very top — so
nothing in between can flip it.

### 0.266.5 — no chasing a scroll target that cannot fit

Once the composer and the pinned heading have taken their share of a short
window, the list can be left with almost no room. Scrolling a row into view
cannot succeed in a viewport that small, so each attempt moved the scroll again
without ever converging. Below a minimum height, the scroll is now left alone.

### 0.266.7 — the heading expands again at the top

A regression from 0.266.3: the heading never expanded at the top of the list when
you were inside an item. Alongside the two thresholds, a third condition refused
to expand whenever the collapsed list was not scrollable — so a note short enough
that collapsing removed its overflow stayed collapsed at the top forever, taking
its Show-more toggle with it. The two thresholds handle the oscillation on their
own, so the extra condition is gone.

### 0.266.0–0.266.5 — diagnostics

The debug trace now records render entry and exit with an id, so overlapping
renders are visible as overlapping; keyboard show/hide; and what *scheduled* each
render, which is what identified the storm-detector bug above.

## Files and navigation

### 0.266.0 — paste a path into the dropzone

The file dropzone accepts a **pasted path**, skipping the system file picker
entirely. Quoted paths, `file://` URLs and shell-escaped spaces are all handled,
since pasting any of those verbatim otherwise fails with "no file at that path"
for a path that is plainly correct on screen. Pasting a folder path opens it in
your file manager and suggests dragging the files in. Desktop only.

### 0.266.1 — quick-switcher shortcuts per folder

A new command, **Create quick-switcher shortcuts for every Stashpad folder**,
writes one small file per folder into `Stashpad Shortcuts/`. Opening one replaces
its own tab with that folder's Stashpad view, so the quick switcher can reach a
Stashpad — it only finds files, and a Stashpad is a folder. Deleting a shortcut
removes nothing but the shortcut.

### 0.266.1 — keybindings saved in an older shape are repaired

A binding stored as a bare string rather than an object was silently skipped and
reverted to its default, so the key you chose did nothing at all. Such bindings
are now converted to the current shape and honoured.

### 0.266.7 — Mod+click a breadcrumb to open it in a new tab

Any part of the breadcrumb — the home crumb, a trail segment, or the breadcrumb
above a row in Flat and Everything modes — opens in a new Stashpad tab on
Mod+click, the same gesture every other link in Obsidian uses. It follows the
platform's own modifier and the existing "new tabs open in the background"
preference.

### 0.266.7 — the heading's context menu targets the heading

Right-clicking the pinned heading opened its menu but left the cursor down in the
list, so a command reached through "More commands…" — which resolves its own
targets — acted on a child row or reported that nothing was selected. A
right-click is an unambiguous choice of *this* note, so it now moves the cursor
the way a left-click already does.

## Duplicate IDs

### 0.266.1 — discard and merge

The duplicate-ID modal gained per-row results, conflicted copies sorted last,
scroll position preserved when comparing, and in-modal resolution with undo. The
Discard button reads correctly on hover, and the verdict labels are spelled out
rather than colour-coded alone.

## Setup

### 0.266.7 — setup can open the side panels

The welcome and setup flow offers to open the folder switcher and the Stashpad
panels alongside the list. Both have had commands for a long time, which is no
help to anyone who does not know the panels exist. It is an opt-out toggle:
closing a sidebar is obvious in a way that discovering one is not.

## Housekeeping

### 0.266.8 — folding no longer sets an inline style

Collapsing a callout set `display: none` directly on the element, which the
community-plugin guidelines advise against and which was redundant anyway — the
collapsed class and this plugin's own stylesheet already hide the content. The
only inline value still touched is the one Obsidian itself writes onto a callout
authored collapsed, which has to be cleared for the content to reappear.
