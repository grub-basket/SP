# 0.295.1

Performance: large folders now render only the rows you can see.

## Windowed rendering (0.295.0, 0.295.1)

- **Folders with more than about 120 notes build only the rows near the
  viewport** (plus a margin above and below) and stand two spacers in for the
  rest, sized from the rows' measured heights. As you scroll, rows leaving the
  window are removed and rows entering it are built. A rendered row is exactly
  what it was before — same markup, same behaviour — so selection, keyboard
  navigation, drag and drop, replies, reactions and edits all work the same.
- On a 424-note folder a full list render went from roughly one second (every
  row built) to a few tens of milliseconds (about 25–35 rows built). Opening,
  filtering, sorting and navigating a big folder are correspondingly faster,
  and creating a note still adds just its own row.
- Anything that needs a specific row — arrowing the cursor to it, jumping to a
  reply's source, restoring your scroll position, revealing a note by id —
  first moves the window so that row exists.
- Applies to plain note lists. Folders whose list interleaves locked
  placeholders or loose (non-Stashpad) files render every row as before.
- **New setting: "Windowed rendering for large folders"** (List display; on by
  default). Turn it off if a large folder scrolls oddly on your device — every
  row is then built up front, as in earlier versions.

## Known limits

- Rows outside the rendered window aren't drag targets, and the in-list picker
  only sees rendered rows, until you scroll them into range.
- Scrollbar size and position are estimates until the rows around you have been
  measured; they settle as you scroll.
