# 0.580.0

This release covers every change since 0.575.4:
- **A new Focus view** for working through today's tasks with a pomodoro timer or stopwatch.
- **Repeating tasks** roll forward wherever you tick them.
- **New files get the date in front of their name.**
- **Note buttons and menus match their settings**, including a separate list of row buttons for mobile.

## Highlights

- **Focus view.** Run "Open Focus view (today's tasks, pomodoro / time tracking)" from the command palette. Search all your notes and add several as today's tasks at once, then track time with a pomodoro timer or a stopwatch. Work in "One at a time" mode with Done & next, or tick tasks off in the list. Unfinished tasks from earlier days are offered for today. Time spent is saved in each note's frontmatter. The timer keeps running when the tab is closed and shows in the status bar.
- **Repeating tasks work everywhere.** Before, only ticking a task in the Stashpad list moved a repeating task to its next date. Ticking it in the Focus view, the Tasks panel, the daily review, the kanban board, the task timeline, a row checkbox or a bulk Complete left it done for good. All of these now follow the task's repeat setting.
- **New files get the date and time in front of their name**, like `2026-10-22-1430-Grocery-List-k7m3pq.md`. A regular file explorer (Finder, File Explorer) then sorts them by when they were made. Change the separator, or turn it off, under Settings → Dates & Time → "Put the date in front of file names". Existing files keep their names. To date them too, use "Add dates…", which shows what would change first and renames files one at a time. "Remove dates…" undoes it. Both need Obsidian's "Automatically update internal links" setting on.
- **Mobile note buttons have their own list.** Settings → Note actions & menus now has "Item buttons — desktop" and "📱 Item buttons — mobile". Hiding React in the mobile list now hides it on a phone: on note rows, the focused note's header and the preview window. Before, the mobile row ignored those settings. Until you change the mobile list, your phone shows the same buttons as before.
- **The star menu shows "Move in list"**, which was in its default list but silently left out. "Outdent" now works from the star menu and row buttons; before, clicking it there did nothing.
- **Customized menus get new built-in items.** If you had reordered the ⋮ (right-click) menu, items added in later versions now appear in it, such as "Appearance & privacy" and "Skip to next occurrence". Hidden items stay hidden. In a customized ⚡ menu, "Add to / remove from Today" appears once, and stays gone if you remove it. "Add action…" can now put back a submenu that's no longer in the menu.
- **The menu settings explain each item.** Rows say what a fixed submenu contains (Copy ▸, Task ▸, Share & export ▸), when an item only shows (repeating notes, once encryption is set up), and when its label changes (Pin / Unpin).
- **Mobile toolbar.** The "jump to a level" button sits left of the command button, and the toolbar fits narrow phones. On a phone, the Split window's "Nest" option fits on one line.

## All changes

### 0.575.4 (changelog)
- Development changelog entries for 0.575.3 and 0.575.4.

### 0.576.0
- Mobile: the jump-to-level (route) button moves from the start of the breadcrumb to just left of the command button in the toolbar (it's last when that button is off). Desktop is unchanged.
- Mobile: the Split window's "Nest lines under each part" option reads "Nest" (the full text stays as its accessible label), so the row fits on one line.

### 0.576.1
- Mobile: on phones 380px wide or narrower, toolbar buttons shrink to 28px with 3px gaps, and to 25px with 2px gaps at 340px or narrower, so the compact-mode toggle no longer runs off the screen edge.

### 0.577.0
- New Focus view (`stashpad-focus`): a Today list built from a multi-select note picker (open tasks first, earlier-day tasks first), drag to reorder, completed tasks below, and a carry-over banner for unfinished tasks from earlier days (move all to today, per row, or clear).
- One-at-a-time mode with a large timer card, Done & next, Skip, and Up next.
- Plugin-level pomodoro (focus, short break, long break every N) and stopwatch, with a status-bar ticker. The state is per device, survives reloads, and only one device runs a given timer even when the plugin folder syncs.
- Time is logged to frontmatter (`focusDate`, `focusLog`, `focusMinutes`). Logging stops at a phase's real end, so a sleep or a throttled window never logs extra time. Each write has an exact undo.
- Commands: open the Focus view, start / pause the timer, stop the timer.

### 0.577.0 (changelog)
- Development changelog notes for the Focus view: the `focusLog` / `focusMinutes` key names and review fixes.

### 0.578.0
- One shared completion rule (`task-complete-fm.ts`, unit-tested): roll-forward and archive modes move the note to its next due date; complete and interval modes keep the note done and create the next one. An already-completed task does nothing (no second roll or copy).
- The rule now applies to the list's Toggle complete, the row / detail-panel / showcase checkbox, the Focus view, the Tasks panel and daily review, the task timeline, kanban Status drops, and the All-notes bulk Complete / Reopen. Their undo restores the due date and Focus state.
- A rolled task completed from today's Focus list shows as done today, with its next date.
- Next-occurrence copies and archive snapshots no longer carry the Focus keys, so tomorrow's copy no longer lands on today's Focus list with today's time.

### 0.579.0
- New `itemButtonsMobile` setting and a "📱 Item buttons — mobile" editor. The desktop editor is now "Item buttons — desktop".
- Until it's edited, the mobile list is worked out from the desktop list each time: React plus the desktop list's custom buttons, which is the mobile row as it was. Nothing changes on upgrade.
- Mobile rows draw their buttons through the same code as desktop, inside one group that stays on the top row in the chosen order. Extras move to the bar under the note.
- React on the focused note's header and in the preview window follows the current platform's list.
- Each list names the buttons that are always on the row (Preview, Make child on desktop, Star menu, ⋮).
- Settings saving: a setting this device never had is now taken from disk instead of being dropped. This protects another device's saved mobile list.

### 0.579.1
- The star menu shows actions from the menu-only list that it can run ("Move in list", which is in its default list). Its settings editor offers the same set.

### 0.579.2
- "Outdent" works from the star menu and row buttons (it was missing from the shared action handler).
- "Move in list" isn't offered on the focused note's own header.

### 0.579.3
- ⋮ menu: a built-in item or submenu missing from a saved custom order is put back at its default position on load. Hidden items stay hidden.
- ⚡ menu: each new default is added to a customized menu once, at its default position (tracked in `zapDefaultsSeen`). A removed one stays removed.
- ⋮ "Add action…" offers submenus that aren't in the menu. The Reset confirmation now points to "Add action…" for re-adding custom submenus.
- The submenu editor offers the menu-only actions too (Move in list, View history, Delete, Obscure, Split out, …).
- "Split out into its own folder…" can be used at the top level of the ⋮ menu.

### 0.579.4
- Menu editor rows describe fixed submenus and their contents, items that only show in some cases, and items whose label changes with the note. An item the ⋮ menu can't show says so.
- The ⋮ editors call the copy action "Copy ▸", as the menu does.
- The ⋮ section's intro explains that hiding an item hides it everywhere in that menu. It also notes that on a narrow desktop row, the ⋮ button lists the row buttons that didn't fit.

### 0.579.5
- `zapDefaultsSeen` is kept in `data.json`, so an older version rewriting the config folder's menu file can't drop it. The ⚡ check is skipped on a launch where the config folder is turned on but not available yet.

### 0.580.0
- New files get a `YYYY-MM-DD-HHmm` prefix (separator: dash, dot, underscore or none). Notes use their `created` time; attachments use their upload time. Applies to new notes, clones (forks keep the source's date), imports (the original time), folder folds, index notes, demo content and next-occurrence copies. Folder home notes aren't dated.
- Settings under Dates & Time: "Put the date in front of file names" (on by default, new files only), the separator with a live example, Add dates… / Remove dates… for existing files, and "Rebootstrap adds dates to file names" (off by default).
- Add / remove dates for existing files (commands `add-dates-to-file-names` / `remove-dates-from-file-names`): a read-only analysis first (counts, examples, skipped files with reasons, an estimated time), then one rename at a time with a Stop button. Old → new names are saved under `.stashpad/rename-logs/`. It refuses to run while "Automatically update internal links" is off, and it updates plain-text `attachments:` entries.
