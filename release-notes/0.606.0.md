# 0.606.0

This release covers every change since 0.600.5:
- **The composer sits right above Obsidian's bottom bar on phones**, without the blank band it used to leave.
- **A keyboard lock button** keeps the phone keyboard open while you work through the list.
- **Toolbar buttons can be set to show on desktop, mobile or both.**
- **Long notifications are shortened**, with a View full button for the whole message.
- **Attachments shared by several folders can be split** so each folder has its own copy.
- **Rebootstrap leaves alone anything that appears after it starts.**

## Highlights

- **Composer position on phones.** The composer's distance from the bottom of the screen is now measured from Obsidian's bottom bar instead of being a fixed number. The blank band under the send button is gone, and the composer stays correct with the full-width bar, the floating bar, and a bar that auto-hides.
- **Keep the keyboard open (mobile).** A lock button on the formatting toolbar stops the phone keyboard from closing, so you can scroll and tap the list while adding a run of notes. You can hide, move or change its icon in Toolbar buttons.
- **Choose where each toolbar button appears.** Settings → Toolbar buttons has a Both / Desktop / Mobile choice for each button, and snippets have a matching option.
- **Shorter notifications.** Long messages, such as lists of file paths, are cut down in the toast. View full opens the whole message with a Copy text button. The notification history uses the same limits.
- **Split shared attachments.** A new command, and an optional step in Rebootstrap that is off by default, gives each folder its own copy of an attachment that several folders use. You get a preview and a size warning first. Each copy is checked byte for byte before links are repointed, originals go to the folder's archive, a log records everything, and Undo puts it back. Files can be marked as always shared.
- **Private files that exist in more than one place.** Deleting a note or a whole Stashpad folder warns you when a copy of its attachment still exists elsewhere. A Find and delete all copies action removes every copy, including sidecar files.
- **Safer Rebootstrap.** Anything created or synced in after a Rebootstrap starts is left for the next run, so it can't act on files that are still being written. A second Rebootstrap can't start while one is running.

## All changes

### 0.601.0
- New built-in toolbar button, Keep the keyboard open, shown only in the mobile composer and saved as `composerKeyboardLock` (off by default).
- While it is on and the composer has focus, taps on the list and other non-text controls still work without moving focus out of the composer.

### 0.602.0
- `ToolbarButtonConfig` gains an optional `platform` of desktop or mobile. A missing value means both, so existing settings need no migration.
- Settings → Toolbar buttons has a Both / Desktop / Mobile dropdown per row. The keyboard lock is fixed to mobile.
- The formatting toolbar skips buttons meant for the other kind of device in the composer, the edit window and quick capture.
- The AI tag fallback respects the choice.
- Snippets gain a matching "Show button on" option.
- Settings rows at phone width no longer squeeze their names.

### 0.603.0
- New `src/notification-text.ts`: `shortenForToast` cuts a message to 200 characters or 5 lines on mobile and 500 characters or 10 lines on desktop, preferring whole lines and word breaks.
- Toasts add a View full action that opens a new modal with Copy text and Close. Notification history rows use the same limits and button.
- `groupPathsByParent` and `formatGroupedPaths` name each parent folder once in a list of paths.

### 0.603.1
- A file with no heading in a grouped path list comes first, so it no longer reads as part of the previous folder.
- Cuts no longer leave stray bold or code markers, or halve an emoji.
- Blank lines at either end of a message no longer count toward its length.
- View full closes the toast, so the toast can't cover the modal on a phone, and the modal carries the toast's own action buttons.

### 0.604.0
- Rebootstrap records the vault's files when it starts, and every step that writes skips files that appeared later: the loose-file sweep, frontmatter backfill, title renames, attachment renames, the OKF rebuild, link conversion, stray re-homing and the date prefix pass.
- Files the sweep imports itself still count as that run's own work.
- Rebootstrap refuses to start while another run is active or just finishing.

### 0.604.1
- Only notes the sweep really created count as the run's own work.
- A loose folder with anything new inside it waits whole for the next run.
- A file linked from a note that appeared mid-run waits for the next run.

### 0.605.0
- New attachment split: a read-only plan and preview, per-folder copies compared byte for byte, repointed links in bodies and frontmatter, and a final check before the original moves to `<folder>/archive/_attachment-originals/<date>/`.
- The original stays in place when a note outside Stashpad or a canvas depends on it.
- A log, Undo, "always keep shared", a size warning, Find and delete all copies, and a warning when deleting a note whose attachment has copies elsewhere.
- New modules `src/attachment-split-core.ts` and `src/attachment-split.ts`, with unit tests for the link rewriter.

### 0.605.1
- The check that links have moved now reads Obsidian's resolved links for every note, and anything still linked keeps the original in place.
- The link rewriter handles single-quoted and parenthesised titles, and an image inside a link.
- Canvas detection covers text cards and runs again at the start of a split.
- Undo keeps a copy that is still linked or used by a canvas and reports it. Each log entry has its own status, so a retry can finish the rest.
- Log paths follow a renamed holding folder.

### 0.605.2
- Fixes a Markdown link pattern that could freeze the app on a line of many bracketed links, with a timed unit test.
- A copy too large to compare no longer lets an original retire, isn't reused by a re-run, and isn't trashed by Undo.
- An Undo entry stays open if a copy couldn't be reached, and the Undo message gives each reason a copy was kept.
- Notes imported from a loose `.stash` count as the run's own work again.
- A short notification no longer keeps blank lines at its ends.

### 0.605.3
- Sidecar files recognised by the `encryptCompanionExts` setting travel with split attachments: each copy gets its own, retired originals keep theirs in the archive, and Undo and Find and delete all copies handle them.

### 0.605.4
- A note restored after a split no longer writes the retired original back to its old path, as long as the content is safe in the archive or a copy.
- Restored notes are repointed to their folder's copy, and a new copy is made from the archive if the folder has none. Undoing a whole folder delete does the same.

### 0.605.5
- Deleting a whole Stashpad folder warns about copies of its attachments that exist elsewhere. Copies inside the deleted folder don't count.
- Review copies lists every surviving copy.

### 0.605.6
- A restored note with a short link that lands on an archived original is now repointed.
- The retired check compares content, so a different file that has since taken the same name is still restored.
- Undoing a folder delete waits longer for the vault to settle and repeats once.
- Sidecars no longer count as copies in the delete warning or appear as their own rows.

### 0.606.0
- Obsidian's mobile bottom bar overlap is measured and published as `--stashpad-navbar-overlap`, with `stashpad-has-navbar` on the body when a bar is shown.
- The mobile composer's bottom margin is the overlap plus 8px, replacing the fixed 110px plus the safe area. With no bar it clears the home indicator.
- The measurement uses the bar's resting position, so auto-hide doesn't move the composer. It pauses while the keyboard is open, and it updates when the bar's mode changes.
