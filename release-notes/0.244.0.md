# 0.244.0

Two fixes and one setting, all in the media viewer added in 0.243.0.

## Fixed: the viewer's toolbar buttons were invisible

Every button in the media viewer's toolbar rendered as an empty grey square.
An `<svg>` inside a flex container is a flex *item*, and with the default
flex-shrink it collapsed to zero width while keeping its height — so the icon
drew nothing at all. The file-type badges elsewhere were unaffected because
those already carried an explicit icon size, which is why the bug looked
selective rather than total.

The icons are now sized and pinned against shrinking, on both the toolbar and
the previous/next arrows.

## File types that open in the viewer are now yours to choose

Previously the viewer claimed a fixed list of image extensions plus PDF.
That list is now a setting — **File types that open in the media viewer** —
so anything you would rather have open in a tab (or in your default app, if
Obsidian is configured that way) simply comes off the list.

The field is deliberately forgiving about how you type it:

- dots are optional — `pdf, .png, JPG` and `.pdf,.png,.jpg` are the same
- case does not matter
- commas, semicolons and plain spaces all work as separators
- leaving it blank restores the built-in list rather than disabling the viewer

The value is saved when you leave the field or press Enter, not on every
keystroke, so a half-typed list is never treated as the real one.

## Fixed: clicking a missing attachment did nothing

An attachment whose file no longer exists is dimmed in the rail, but clicking
it was silently ignored, which reads as a broken button. It now tells you the
file could not be found.
