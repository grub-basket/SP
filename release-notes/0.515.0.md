# 0.515.0

Fixes for the "Show more" toggle on long notes and for clicks inside the file
preview, plus code-fence wrapping for selected text. Covers everything since
0.511.0.

## 0.512.0 — "Show more" toggle no longer goes missing on long notes

- A note could show in full, with no collapse/expand toggle, even though it was
  far taller than the collapsed size. The reported case was a short code block
  whose middle line ran to thousands of characters.
- Cause: whether a note overflows its collapsed height is measured once, and
  the result is cached with the note's rendered body. That cache persists across
  restarts and is keyed only by list width, so a wrong "it fits" result stuck
  until the note was edited. A wrong result could come from an older build's
  clamp styling (code blocks used to collapse to almost no height, which
  measured as "fits") or from a row measured while it wasn't laid out.
- Cached results now carry a version (`OV_MEMO_VERSION`). Results from earlier
  builds are re-measured once, without discarding the cached rendered HTML.
- A row that isn't laid out (zero height) is no longer cached as "fits".
- New character-count fallback: a note longer than 2,000 characters always gets
  the toggle, whatever the measurement says. No body that long fits the
  collapsed size at a realistic pane width. In a very wide pane, a note just
  over the limit may show a toggle that changes nothing visible.

## 0.513.0 — clicking the image in the file preview no longer closes it

- On desktop, clicking an image in the file/attachment preview closed the
  preview. The preview captures the pointer so you can drag to pan, and that
  made the browser report the click as landing on the empty area around the
  image, which closed the preview. The press origin was then checked as well.
  (Superseded by 0.514.0, which removes click-inside-to-close entirely.)

## 0.514.0 — the file preview closes only on a click outside it

- Clicking anywhere inside the file preview, on the image or on the empty area
  around it, no longer closes it.
- Close it by clicking outside the preview window, with Esc, or with the close
  button. On mobile, where the preview is full-screen, use the close button.
- Panning, pinch-zoom, wheel zoom, double-click zoom and cropping are unchanged.

## 0.515.0 — three backticks on a selection make a fenced code block

- In the composer and the edit modal, select text and press the backtick key
  three times to get a fenced code block: the opening ```` ``` ````, the text,
  and the closing ```` ``` ```` each on their own line. Previously the third
  backtick produced inline ```` ```text``` ```` on one line.
- A selection in the middle of a line splits the line around the block, with
  no stray spaces left at the split points.
- Inside an indented list item, the fences and the first code line keep the
  indent.
- The caret lands right after the opening fence, ready for a language tag
  (`js`, `python`, …).
- One or two backticks still wrap the selection as inline code, as before.
  Wrapping follows the same auto-pair settings as all other wrapping.
