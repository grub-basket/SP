# 0.565.0

This release covers every change since 0.555.0. The biggest addition is a set of tools for reorganizing Stashpad folders: **fold** a small folder into a bigger one, **unfold** it back out later, and **split** a note out into its own folder. A new **folder setup** window sets a folder's icon, placement and blur in one place. Showcase comments can now mark an **area or an arrow** on a picture, not only a single spot. In a narrow list, the floating **note buttons** no longer cover the note's text, hide while you select text, and fold into the **⋮** menu as the list gets narrower. Picked tags now always get a space after them.

## New

### Fold, unfold and split folders

- **0.558.0** — **Fold (merge) a Stashpad folder into another one.** Use the "Fold (merge) this Stashpad into another folder…" command, or "Fold into another folder…" on a folder's right-click menu in the folder switcher. Pick the destination, confirm, and it's done, with Undo.
  - The destination gets one new note at its top level, named after the old folder. The old Home note's text goes in its body. Every note from the old folder moves under it, with its attachments. Note ids are kept unless they clash with one already in the destination. A clashing note gets a new id, and links to it are updated.
  - A **"Folder settings from <name>"** note is pinned to the bottom of that container. It lists the old folder's settings that don't carry over: icon, blur, folder-switcher placement, filters, encryption preferences, template and colour names.
  - The old folder's archive and trash merge into the destination's, under `from-<name>/`. Leftover attachments go to `_attachments/from-<name>/`. Author files the destination doesn't have yet are copied into its `_authors/`.
  - The emptied folder is moved, not deleted, to `_archive/Folded Stashpads/<name>`, with a record of the fold. This happens last. If any earlier step fails, the steps already done are rolled back and the old folder stays where it was.
  - If the folded folder was your default folder, the default moves to the destination.
- **0.559.0** — **Folding also moves locked (encrypted) notes.** They're unlocked with the old folder's key, moved, and locked again with the destination's key. You may be asked for both passwords.
  - Locked notes are unlocked straight into the destination, never through a trash, so no plain-text copy is left in the system trash.
  - If locking with the new key fails, the note is locked again with the old key and stays in the archived folder. The confirm window tells you up front what will happen, and the notification after the fold counts the re-locked notes and says why any were left behind.
  - Undo puts back the original encrypted files exactly.
  - "All archived" lists locked notes in a folded folder's archive under that folder's archive.
- **0.560.0** — **Unfold a folded folder** (split it back out). A fold's Undo only lasts until you reload Obsidian. Unfold works any time afterwards, using the record the fold left behind.
  - Use the "Unfold a folded folder (split it back out)…" command, or "Unfold a folder folded in here…" on a folder-switcher row. That item only shows on folders that something was folded into.
  - The archived folder goes back to its old place. Everything under the container note becomes its top level again, including notes added since the fold. Archive, trash, attachments and author files go back too. Locked archive notes are locked again under the old folder's key.
  - Unfold refuses if the old folder name is taken again, or if the archived folder or the destination is gone. It can be undone (which folds the folder again).
- **0.561.0** — **Folder setup window.** It sets a folder's icon (with a live preview), its folder-switcher placement (Normal, Pinned, Downranked or Hidden), and its blur (follow the global setting, always or never), all in one place. If the folder already has an encryption key, it also offers "Encrypt notes in this folder".
  - It opens right after you create a new folder. Nothing changes until you press **Done**. Skip, Cancel and Escape leave everything as it was.
  - **New setting:** "Set up new folders" (Folders & storage, on by default) turns the window off.
  - **"Edit folder…"** on a folder's menu in the folder switcher opens it for any existing folder.
- **0.562.0** — **Split a note out into its own Stashpad folder**, the reverse of a fold for one note. "Split out into its own folder…" is in the note's **Move** submenu, the quick menu and the right-click menu.
  - You name the new folder; the name is pre-filled from the note's first line. The folder is created next to the current one.
  - The note's text becomes the new folder's Home note. Its children become the new folder's top level, and grandchildren keep their nesting. The note itself goes to the trash.
  - Locked children stay where they are, because the new folder has no key yet. The prompt says so.
  - The folder setup window opens afterwards, unless "Set up new folders" is off.
  - Undo moves everything back, restores the note, and moves the new folder to the vault's `.trash`. Nothing is deleted. An existing folder name is refused.

### Showcase: comment on an area or with an arrow

- **0.556.0** — A Showcase comment can now **mark an area (a box) or point with an arrow** on an image or PDF page, not only drop a pin on one spot.
  - Start a comment as before. A click still drops a pin. **Dragging draws a shape**, with a live dashed preview. While you pick a spot, a **Box / Arrow** switch shows in the file's header; your choice is remembered for next time.
  - The comment box opens below the whole shape, so it doesn't cover what it's about. Its prompt follows the shape ("What about this area?").
  - Saved boxes show as outlined areas and arrows as arrows: orange while open, green once resolved. The numbered pin sits at the box's top-left corner or the arrow's tail.
  - Hovering or focusing a comment lights up its shape. A box dims the rest of the picture (a spotlight), and an arrow glows.
  - Each comment with a shape shows a **close-up** of the area. Clicking it, or the comment's "on file · area" chip, scrolls the shape into the middle of the view and flashes it. Arriving from a list's "Feedback on …" chip does the same.
  - Drawing works with touch as well as a mouse.
  - The HTML export draws boxes and arrows too, and says "· area" or "· arrow" on the comment line.
  - Older Stashpad versions still show these comments as pins in the right place.

### Note buttons in a narrow list

- **0.565.0** — When the list is 700 pixels wide or less, each note's buttons appear as a small floating toolbar when you hover the note. That toolbar now stays out of the way of the note's text.
  - It sits across the note's top edge, over the gap between notes, instead of on top of the first line. Its buttons are a little smaller there.
  - Where there's no room above (the first note, a note scrolled up to the top, or one tucked under the sticky heading or the view-in-context bar), it moves back inside the note's corner, just below the heading or bar.
  - **It hides while you select text.** Any note that your selection touches hides its toolbar while you drag and while the text stays selected. It comes back once the selection is cleared. A selection that only touches the very start of the next note doesn't hide that note's toolbar.
  - **It shrinks as the list narrows.** The toolbar takes at most 40% of the note's width. Buttons that don't fit move into the **⋮** menu, starting from the right. At its narrowest the toolbar shows only Show more and **⋮**. A button that has keyboard focus is never moved.
  - The buttons that moved are listed first in the **⋮** menu, with their usual icons. Picking one works the same as clicking the button, and pop-ups such as the reaction picker still open next to the note.
  - Wider lists, phones, and touch-screen computers without a hover pointer work the same as before.

### Tags

- **0.564.0** — Picking a tag from the autocomplete list always adds a space after it, whether you pick it with Enter, Tab, a click or Space. Before, only Space did, so the next word you typed ran into the tag. If a space already follows, the cursor steps over it instead of adding a second one. Works in the composer and the edit window. (Built as 0.557.0 and renumbered to 0.564.0 before release.)

## Fixes

- **0.560.1** — Encrypted notes in a folder's trash were added back on every launch as live "locked note" placeholders. Trashed encrypted notes are no longer counted as live. They stay on disk and in the Trash view.
- **0.562.1** — Fixes to fold, unfold and split after an independent review that looked for ways to lose data or leak plain text:
  - If a move failed partway through, the steps already done couldn't always be undone, and a split's rollback could move notes into the vault's trash along with the new folder. Undo steps are now recorded as each step completes, and the new folder is never moved to the trash while real notes are still in it.
  - Undo now first checks that nothing has changed since. A fold's Undo run after an Unfold used to overwrite newer edits; now it says "Nothing to undo" instead. If an important undo step fails, the rest stop.
  - If re-locking a note fails with both keys, the original encrypted file is written back before any unlocked copy is removed, so no plain text is left behind.
  - Re-encrypt reminders move with their notes when you fold, unfold or split, and move back on undo.
  - Unfold checks the fold's record against your settings and refuses a record that doesn't match.
  - Folding a folder that already had other folders folded into it no longer nests `from-` folders two levels deep, and unfolding reverses each one exactly.
  - Undo only touches the folded folder's own locked-note entries, placement and default-folder setting, not those of other folders.
  - Unfold restores the folder's placement and default-folder setting. Pressing Enter on a focused Skip or Cancel button in the folder setup window no longer applies the changes.
- **0.565.0** — Fixes from testing and an independent review of the narrow-list toolbar:
  - Obsidian fixes button height, so the toolbar's smaller buttons now set their height directly.
  - A note scrolled up under the sticky heading had its toolbar hidden behind the heading. It's placed just below the heading now.
  - The sticky view-in-context bar is treated the same way.
  - Scrolling with the pointer resting on a note now re-places that note's toolbar.
  - A button added to the toolbar while the pointer was already on the note (such as Show more) now counts towards the width limit.
