# 0.268.6

Attachments and imports got most of the attention here: notes named after the
file they hold, `.stash` bundles that import when you drop them, and a proper
home for imports that fail.

## Notes named after what they hold

A note whose first line is only a link or an attachment used to be called
"Untitled". Those are exactly the notes with no prose to borrow a name from,
since they are usually created by attaching a file, so every one of them ended
up with the same useless name.

They are now named after what they point at, with the kind of thing in front:

- an embedded image becomes **Attachment PNG Holiday Photo**
- a link becomes **Link Why Rust Is Fast**
- an Obsidian deep link becomes **Deeplink Open**

Text still wins. A note with anything to say is named after what it says,
whether or not a link sits beside it.

### Attaching a file names its note

The file's name now goes in front of the file itself, separated by a space, so
an attachment note reads as "quarterly-report.pdf" rather than showing up blank
in the list. There is a setting if you prefer it did not.

### Files without the embed

Attachments can be inserted as a plain link instead of an embed, which suits a
note holding several files that you would rather read as a list than scroll
through as previews. Either way the file appears in the rail: it now recognises
a file by its extension rather than only spotting embeds.

## Dropping a bundle imports it

Dropping a `.stash` on the composer used to attach it as a file, which meant it
was never imported and never asked for a password. It now imports.

Drop a mixture and each part goes where it should. Bundles import, encrypted
ones wait for a password at a time you choose rather than interrupting with a
modal, and everything else attaches as usual. You get one summary for the batch
rather than a notification per file.

### Imports that fail have somewhere to go

A bundle Stashpad cannot read moves into a `_failed-imports` folder with a note
beside it recording the file, the time and the reason. Previously it was left
where it was, which made it indistinguishable from a bundle waiting for a
password and meant Stashpad tried and failed to import it again on every pass.

It is moved, never deleted. Stashpad could not read it, so it cannot know what
it was worth to you. Move it back up a level to try again.

The record is a markdown file with frontmatter, so a Base can list every failed
import with its reason and date rather than making you open the folder.

## Optional link rails

Under a note's files, two optional rows: the notes this one **links to**, and
the notes that **link back**. Both off by default, and separate from each other,
because "what does this point at" and "who refers to this" are different
questions.

Stashpad's own internal parent and child links are excluded, so a backlinks row
shows notes you linked rather than the tree you are already looking at.

## Smaller things

- The command line tool in the repo gained `move`, so a note can be reparented
  from a terminal. Previously that needed the picker, which a terminal cannot
  open.
- The debug trace records which code asked for a render, and repeated identical
  lines collapse to a count so more history fits.
