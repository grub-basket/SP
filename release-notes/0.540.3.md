# 0.540.3

This release covers every change since 0.540.2. It fixes the **Show more** and collapse buttons after you resize the Stashpad list.

## Fixes

- **0.540.3** — **Show more / collapse buttons stay correct when the list is resized.**
  - Each note decided once, when it was drawn, whether it needed a **Show more** button. Resizing the list never made it re-check.
    - After widening the list, a note could stay fully open with no way to collapse it.
    - After narrowing it, a note that now fits could keep a **Show more** button that did nothing.
  - This was more noticeable since 0.540.0. When the list crosses 700px, the note buttons move out of the text's way, so the text width changes a lot all at once.
  - Notes on screen now re-check shortly after the list's width changes. A **Show more** button that's no longer needed is removed. Expanded notes keep their **Show less** button.

## Internal

- The list's existing resize observer now watches for width changes. 150ms after the resize settles, it re-checks the visible notes in one batch, using the same measuring code that runs when the list is drawn. Height-only changes are ignored.
- The code that finds where the **Show more** button goes is now a shared helper, `rowToggleAnchor`, used by both the resize re-check and the single-note repaint.
- Merged the fix branch into main. Developer coordination notes were updated; they don't ship in the plugin.
