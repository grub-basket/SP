# 0.268.17

One long-standing bug in the settings window, two real speed-ups, and a
keyboard fix. Most of the versions in between built the diagnostics that found
them, which are listed at the end.

## Settings stopped responding after opening Hotkeys

Opening the Hotkeys section could leave the rest of Stashpad's settings
unclickable. Every other section worked normally until Hotkeys was visited, and
restarting Obsidian cleared it, which made it look intermittent.

It was not intermittent. Settings are re-read when another device changes them,
and that path replaced the whole keyboard-shortcut map with the incoming copy.
A device running an older version sends a map that predates a command added
since, so the receiving device ended up with a map missing an entry. Building
the Hotkeys list then failed on the row for that command, and the failure took
the settings navigation down with it. Restarting fixed it because startup
rebuilds the map from the shipped defaults.

Three things changed, so that no single missing entry can do this again:

- Incoming settings are re-merged against the defaults, so a map arriving from
  an older version can no longer be short an entry. Nothing is lost: values
  that are present are kept, and only the absent ones return to their defaults.
- A shortcut row with no stored entry restores it at its shipped default
  instead of failing.
- A row that cannot be drawn is now contained and replaced by a placeholder.
  One bad row is not a reason to lose the settings window.

## Speed

**Saving a setting no longer repaints every open Stashpad.** A change to any
setting told every open view to rebuild, including tabs in the background
holding hundreds of notes. Composer drafts save as you type, so this ran
constantly. Views now repaint only when something that affects them actually
changed.

**Background tabs stopped rebuilding while off screen.** Suppression for tabs
that are not visible existed but inverted itself after its first use, so one
rebuild was skipped and every later one ran anyway. A single settings save was
rebuilding a 714-note list and two 342-note lists that nobody could see. Those
tabs now wait and rebuild when they are opened, so their contents are still
current when you switch to them.

## Mod+A in the composer

Select-all works in the composer again. The chord was being claimed globally
elsewhere; Stashpad now records when a keypress reaches it and when it does
not, so a conflict of this kind can be identified rather than guessed at.

## Diagnostics

The debug trace, which is off by default, gained the instrumentation used to
find the above:

- A copy is written beside the settings file about once a second, so a trace
  survives a crash or a force quit. On the next start the previous session's
  copy is set aside rather than overwritten, and a new command copies it back
  out. Switching the trace off deletes both copies.
- A synchronous snapshot covers the case an ordinary write cannot: if the app
  stops responding entirely, a write that has to wait its turn never happens.
  The snapshot is taken at least every quarter second.
- A heartbeat records when the main thread last ran, so a session that ended
  abruptly reports when it stopped rather than only what it last did.
- A stall detector reports any pause long enough to notice, with how long it
  lasted and what ran immediately before. It reports on a window that is not in
  the foreground too, above a higher threshold, so that ordinary background
  timer slowdown is not mistaken for a pause.
- Every settings section is timed, slowest first, and a section records when it
  starts drawing as well as when it finishes, so a section that never finishes
  is visible as such.
- A settings-window snapshot command reports what is actually on screen and
  what is receiving clicks.
- Trace history was extended from 300 to 900 lines to match the extra detail.
