# 0.368.0

## Cross-vault paste now shows the subtree nested (no reload)

When you pasted notes from another vault, the receiving vault showed them **flat** until you reloaded — even though the children had been copied. The paste rebuilt the list before Obsidian had finished reading each new note's parent, and an internal shortcut (added for list performance) couldn't tell that the notes had been re-nested, so it never corrected them.

- After the first paint, the paste now **waits for the new notes to be fully read, then re-nests them** — so the subtree shows correctly without a reload. A brief "Organizing N pasted notes…" message covers the moment.
- Applies to both cross-vault paste paths (the fast folder transfer and the clipboard/zip fallback).

Also confirmed: a cross-vault **copy already includes the whole subtree** — copying a parent always carries its children. The earlier flat display just made it look like they were missing.
