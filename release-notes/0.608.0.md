# 0.608.0

This release covers every change since 0.606.0:
- **Folder icons no longer reset when two devices have the same vault open.**
- **Settings changes from other devices are picked up right after you turn on, move or turn off the config folder**, without reloading Obsidian.

## Highlights

- **Folder icons survive syncing between devices.** Folder icons used to be saved as one block. When another device saved an older copy of Stashpad's settings, this device could take that whole block and lose every icon set since. This happened when the other device opened before the sync caught up, ran an older Stashpad, or when Obsidian Sync merged two copies of the settings file. Each folder's icon now records when it was set or cleared and what it was set to. Devices merge folder by folder and the newer change wins. A folder that is missing from the other device's copy is never treated as a removal, and clearing an icon still reaches every device. Each device also keeps its own local copy of its icons, so they come back even if an older copy arrived while the app was closed.
- **What to expect while devices are on different versions.** Full protection needs every device on this version. Until then, icon changes made on a device still running an older Stashpad may not stick on folders whose icon was already edited on this version. Icons set before this version have no timestamp yet. If two devices disagree about one, picking it again once settles it.
- **Config folder changes are picked up live.** With "Store config in a vault folder", turning it on, moving it or turning it off during a session used to leave the new files unwatched until Obsidian reloaded. Changes from your other devices (snippets, saved views, menus, templates, folder appearance) are now noticed right away.

## All changes

### 0.607.0
- New setting `folderIconStamps`: per folder, the time of its last icon change and the icon it was set to (`null` = cleared). Where a folder has a stamp, the stamp decides its icon; `folderIcons` is kept as a plain copy for older versions.
- New module `src/folder-icon-merge.ts`: cleans one copy, stamps local edits by comparing with the last known icons, and merges two copies folder by folder. The later stamp wins; a missing folder is never a removal; ties between unstamped or same-moment icons pick the alphabetically later icon id, so every device reaches the same result. Cleared stamps expire after 180 days.
- Every place that edits icons (icon picker, folder setup, folder rename and move, folder merge) is stamped automatically, without changes to those features.
- The settings save merges the icons with the copy on disk before writing: `data.json`, or `appearance.json` when the config folder is on.
- The external-change watcher merges incoming icons the same way and writes the repaired copy back right away when the file lost icons.
- In config-folder mode the settings store never adopts the icon keys wholesale, `appearance.json` also carries `folderIconStamps`, and a copy that an older version rewrote without the stamps is repaired.
- At load, the device's local copy of its icons is merged in, so icons survive an older copy that arrived while the app was closed.
- Restoring a settings backup stamps the restored icons as new edits, so they win on every device.
- Tabs and the Folders panel repaint when a merge changes a folder's icon.
- New unit tests: `scripts/tests/folder-icon-merge.test.ts`.

### 0.608.0
- The external-change watcher rebuilds its list of watched settings files when the config folder is turned on, moved or turned off. It used to build the list once at startup, so those files went unwatched until a reload.
