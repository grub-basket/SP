# 0.535.0

This release covers every change since 0.534.1. If you use **New tabs open in the background**, switching folders now brings the folder's tab to the front, so you land where you chose. Notes, attachments, reminders and other new tabs still open in the background.

## Windows & tabs

- **0.535.0** — New setting: **Switching folders always brings the tab to the front**. It's on by default and sits under **New tabs open in the background** in Settings → Windows & tabs.
  - It's an exception to the background setting. When you switch folders, the folder's new tab takes focus even while other new tabs stay behind you.
  - These count as switching folders:
    - picking a folder in the folder switcher, including creating or converting one there
    - the folder menu in a Stashpad tab's header
    - a folder picked in Search
    - every way the folders panel opens a folder: clicking a row, the new-tab button, and the **Open in new tab** menu items
    - the file explorer's **Open folder in Stashpad**
  - Everything else follows **New tabs open in the background**: notes, attachments, reminders, the aggregate, tasks and trash views, links, and **Go to folder** buttons on notifications.
  - It only does something while **New tabs open in the background** is on. Turn it off to keep folder switches in the background as well, like before.
  - If you already have background tabs on, folder switches will come to the front after you update, because the new setting starts on.

## Internal

- New-tab focus is decided in one shared helper, `settleNewTab`. It now takes an optional `folderSwitch` flag, which the folder-open paths (`activateViewForFolder`, `openFolderInStashpad`, `createOrRedirectAndOpen`) pass through.
- Developer coordination notes recording the 0.534.1 release. They don't ship in the plugin.
