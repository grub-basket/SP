# 0.268.18

A follow-up to the diagnostics added in 0.268.17.

## The debug trace no longer writes to disk unless asked

The debug trace is a troubleshooting aid, off by default, that records what
Stashpad is doing while a problem is reproduced. In 0.268.17 it also kept a copy
on disk, so that a bug severe enough to require force-quitting Obsidian would
not take the recording with it.

That copy was written continuously for as long as the trace was on: a file
update roughly every second and a marker every quarter second. Useful for a
crash, and not worth paying for the rest of the time.

Saving to disk is now its own setting, **off by default**. With it off, turning
the trace on records everything in memory as before and writes nothing at all,
so both "copy the trace" commands work exactly as they did. Turning it on
restores the crash-surviving behaviour, and turning it off again deletes the
copies it made.

The main toggle's description no longer claims a copy is always written, since
that is now up to you.
