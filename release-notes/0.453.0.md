# 0.453.0

## 0.452.0 — encryption: companion-history coverage for notes' sidecars and attachments

Extends the encrypted-lock feature so third-party version-history sidecars (e.g. the Edit History plugin's `.edtz` files) are protected, not left readable on disk.

- **Note companions are now actually matched.** The companion resolver matched `<basename><ext>` (e.g. `Foo.edtz`), but history plugins append their extension to the full filename (`Foo.md.edtz`), so with the default `.edtz` setting nothing was ever caught. It now matches both the full-filename and the basename forms, for notes and attachments alike.
- **Attachment history is encrypted too.** When a subtree is locked, the companions of its attachments — including embedded `.canvas` and `.base` files — are bundled into the encrypted blob and purged from plaintext, then restored beside the attachment on unlock. Companion resolution for a subtree's notes and attachments happens in a single de-duplicated walk so a companion is bundled if and only if it is purged.
- **Shared attachments keep their history.** An attachment referenced by an external note stays in plaintext on lock; its companion now follows the same rule rather than being deleted.
- **Cleaner "couldn't remove plaintext" reporting.** A history plugin often deletes its own sidecar as a side effect of the note being deleted, so the companion is already gone by the time the purge runs. An already-absent companion now counts as removed; only a companion still present after a failed delete is reported.
- The orphaned-companion sweep recognizes the full-filename owner convention, so genuinely paired sidecars are no longer mis-flagged as orphans.
- Plain `[[links]]` to canvas/base files are intentionally left untouched (only embedded/attached files ride into the blob). The lock confirmation copy and the companion-extensions setting description are updated to reflect notes and their attachments.

## 0.453.0 — file preview renders embedded bases; canvas gets an identity card

- **Bases render in the file-preview modal.** A `.base` slide now shows the base's live table view on the stage, via Obsidian's own embed, scrollable alongside the existing image, PDF, text, and note slides. It falls back to the file-fact card with an open-in-a-new-tab button if the embed can't render.
- **Canvas files get a proper identity card.** A `.canvas` shows a dedicated "Canvas" card (icon, label, colour) immediately, with a one-click open-in-a-new-tab to the real canvas view. Obsidian renders an embedded canvas as a title card rather than the node graph outside a full editor, so the preview does not attempt a graph render that would only flash and fall back.
- Canvas and base files now have their own file-type identities (icon/label/colour) in the attachment rail and preview card instead of a generic file icon.
- Internal: the modal's unpreviewable-type branch is refactored into one shared file-card renderer.
