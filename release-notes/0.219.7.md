Adds an importer for data from the discontinued Stashpad desktop app, and a round of work on the note list — some of it confirmed, some of it still under investigation. See the honesty note at the end.

## 0.216.0 – 0.217.1 — Import from the old Stashpad desktop app

- **New importer for the discontinued Stashpad desktop app.** Bring across notes from an export of the old app, with its indentation quirks handled: that app wrote the top parent with no bullet and no indent, its children with a bullet but still no indent, and only began indenting at the third level, so by indentation alone the first two levels were indistinguishable.
- Labelled sections in the import preview, and the app's non-note data is brought across too.
- Pinned state and orphan grouping are preserved through the import, with a guard against re-running it over content that is already there.
- Task prefixes are guarded during import, so a line that already starts with a checkbox does not end up with two.

## 0.217.0 – 0.219.2 — The note list updates in place

- **Changing a note's color, ticking a to-do, or entering select mode no longer rebuilds the whole list.** Those change how a row looks, not what the list contains, so the rows are now repainted where they are. Beyond the visual steadiness this avoids a full rebuild of every row on screen for what is a one-row change.
- Colors set from anywhere — a command, the menu, undo, another window, or a sync — update in place, not just the ones set from the list.
- **Opening a folder no longer paints a different folder first.** The view could render the default folder's notes before switching to the one being opened, building a full list only to discard it a moment later.
- Spelling of "color" is now consistent throughout, matching Obsidian's own terminology.

## 0.219.3 – 0.219.7 — Repeated rebuilds after every edit, and duplicate note ids

- **Fixed a background check that could rebuild and re-render the entire list after every single edit.** It compared the number of notes on disk against the number in the index, and counted notes inside `_archive` and other reserved subfolders that the index deliberately ignores. Any folder that had ever archived a note therefore never matched, and re-checked forever.
- It also no longer retries a difference it has already failed to close. If a rebuild does not change anything, re-running it cannot help either.
- **New: duplicate note id detection.** When two notes carry the same id they collapse into a single row, so one of them is invisible in the list even though the file still exists. Stashpad now notices this and offers a **Review duplicates** view showing each affected id, every file using it, and which one is currently shown versus hidden. Clicking a file opens it. Nothing is changed automatically — a repair command is planned.
- **New command: "Find duplicate note ids".** The automatic warning can only notice the folder you have open, so this checks every Stashpad folder at once.
- Duplicates almost always come from copies that kept their frontmatter: a re-import, a restored backup, or a sync conflict copy. Until the repair command exists, giving one copy a different `id` in its frontmatter makes it visible again.

## An honest note on the list movement

Several of the changes above were made while chasing a report that the list scrolls on its own when changing a color or marking a to-do. **That is not fully resolved.** Each change here is a real improvement — less work per edit, fewer rebuilds, one genuine root cause fixed — and the movement is reduced. But it has not been confirmed gone on device, so they are offered as attempted fixes rather than a promise.

If you see the list move on its own, turning on **Debug trace** in Settings → Diagnostics, reproducing it once, and sharing the result would help — it records what moves the list and what wrote to it, which is how the cause above was found.
