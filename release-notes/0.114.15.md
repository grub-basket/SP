# 0.114.15 — Per-folder encryption, key rotation, and encrypted-note export

This release overhauls vault encryption into a **per-folder** model with manual
password sharing, adds **key rotation**, an **export path for locked notes**, and a
set of keychain-reliability fixes. Everything since `0.113.0`.

## Keychain reliability (0.113.1–0.113.3)
- Encryption notices now read **"Settings → Stashpad → Encryption"** (Stashpad's own
  settings, not Obsidian's) so the path is unambiguous. Native-Obsidian paths
  (`Settings → Files & Links`) are left as-is.
- **Setting a shared password now keeps this device's keychain in sync** with it —
  previously the device kept serving a stale password, so auto-unlock used the old one
  and "paste from keychain" returned the wrong value.
- **Stop silently zeroing the saved keychain password.** Setup / set-shared-password /
  change-password / request-access used to clear the saved password whenever the
  "Remember" box was unticked. Now they never auto-forget — only the explicit "Forget
  on this device" action and remove-encryption clear it — and password changes update
  the saved copy instead of leaving it stale.

## Per-folder encryption (0.114.0–0.114.8)
- **Per-folder keys.** Each top-level folder can have its **own password** (a separate
  key), so you can share just that folder with collaborators. Folders without their own
  password fall back to the vault password, so existing encrypted content is unaffected.
- **"Per-folder passwords" settings section.** Set / unlock / change a folder password,
  lock or unlock a folder's notes, and per-folder toggles for archive, trash handling,
  and encrypting content + filenames for the folder, its archive, and its trash.
- **Aggregate tabs.** New "All encrypted" and "All archived" views list everything in
  one place, grouped by folder (read-only; they never decrypt).
- **Old passwords are retained, never deleted.** Changing a password relabels the prior
  one `[deprecated]` and keeps it (and parks the old keychain entry) for recovery —
  but a deprecated password can no longer unlock current content.
- **Keychain entry names** follow a readable `date – folder – author-initials`
  convention instead of an opaque random id, and stay within the platform's
  secret-id rules.
- The dedicated "Forget password on this device" buttons were retired (passwords are
  retained, never deleted); the device-approval ("collaborators") UI is hidden in
  favor of manual password sharing. The underlying code is kept, just dormant.

## Key rotation (0.114.9, 0.114.14)
- **Rotate a folder's key** ("when someone leaves the org"): re-encrypts every locked
  note in the folder under a brand-new key, then retires the old password so it can no
  longer decrypt — true invalidation, unlike a cheap password change.
- Rotation is **crash-safe**: it writes verified temp copies (originals untouched),
  swaps the key, then commits — and finishes or cleanly rolls back an interrupted
  rotation on the next launch, using an on-disk nonce so it can always tell whether the
  swap actually happened.

## Export locked notes (0.114.15)
- **Export an encrypted note as a shareable `.stash`.** From the locked-note menu or
  the "All encrypted"/"All archived" tabs, export a virtual copy re-encrypted under a
  **new password you choose** in the export dialog. The original locked note is left
  untouched. (A locked note's on-disk file is encrypted to the vault/folder key, not a
  password, so it can't be shared as-is — hence the re-encrypt.)

## Archive, trash & settings fixes (0.114.10–0.114.13)
- **Archive command:** if the notes are already in an archive folder, it now says so
  instead of silently moving them to a *different* archive (which also caused the
  default-archive target to be ignored).
- **"All archived"** lists the archived notes grouped by folder (not just folder names).
- Toggling an encryption-dependent setting (encrypt trash, hide titles, …) with no
  encryption set up now walks you through setting it up first.
- The "Default archive folder" is set from the single dropdown in settings (the
  redundant per-folder "default target" button was removed).
- The per-folder settings are now a **folder dropdown + one dynamic panel** instead of
  a long list of every folder, and sit below the global encryption settings.
- "Hide titles of locked notes" is now the **default** that per-folder filename
  options can override.

## Notes
- A folder's trash uses the vault key for now; per-folder trash keys and subfolder key
  inheritance are planned follow-ups.
