# 0.316.7

A big batch: the note-list "always land at the bottom" work is finally solid on
mobile, two sidebar surfaces became real tabs, the emoji reaction picker was
reworked, and the All-notes view gained the search modal's filter chips.

## Note list — landing at the bottom (the "R1" work)

Opening, switching, or starting up a folder is meant to land you at the newest
note at the very bottom. On mobile that had a flicker-and-land-short problem;
this release resolves it in stages:

- **Always pin to the bottom on open / switch / startup** — a folder open,
  folder switch and app startup now all use one deterministic bottom pin instead
  of chasing a saved scroll anchor that left the list a few notes short.
- **Cancel stale settle loops** — each render during a folder open
  (empty → partial → full) and each rapid folder tap used to spawn its own mobile
  "settle" loop with no cancellation, so stale loops fought the newest one and
  landed short. A pin token now makes every settle loop bail the moment a newer
  pin supersedes it or its list detaches.
- **Honour the pin on re-renders** — an async re-render that carries no scroll
  policy (tree rebuild / frontmatter sync finishing) no longer restores the old
  mid-list scroll while the view is still in "pinned to bottom" intent; it
  re-pins instead. Applied to both the policy-less path and, in 0.316.7, the
  `preserve` render path — the reconcile pass that renders the real (much taller)
  note bodies ~1.5s after a switch was growing the list by thousands of pixels
  and stranding the view mid-list; it now re-pins to the true bottom.
- **Stop the settle loop once it is actually settled** — the mobile settle loop
  used to run a fixed number of ticks even after it was already at the bottom;
  that idle re-pinning was a window where a late repaint or a stray touch got
  yanked. It now stops as soon as the height holds steady at the bottom for a
  couple of ticks, and keeps pinning through late row-growth until then.
- **Hide until settled** — a freshly opened / switched folder's list is rendered
  hidden (layout intact) across its empty → partial → full paints and revealed
  only once the bottom pin has settled, so those three intermediate paints no
  longer flash in at three different scroll positions. A hard safety timeout
  guarantees the list is always revealed.
- Added opt-in local debug tracing for the scroll behaviour (no telemetry, no
  network) to diagnose the mobile-only cases.

## Notifications and Log are now dedicated tabs

The notification history and the per-folder action log opened as modals. They
are now full **tabs** (reachable from the view launcher and reusable like any
other view), each with the same toolbar, filters and pagination as before. The
underlying render logic is shared with the (still available) modal wrappers, and
the tabs fill their space instead of sitting in a narrow modal-sized column. The
notifications tab's "Open log" button jumps to the log tab.

## All-notes view — filter chips

The "All notes" master index gained the note-search modal's **`in:`** and
**`when:`** filter chips on their own row, with the facet chips (Files / Imported
/ [[links]] / http / Orphans / …) moved onto a line of their own below. The chips
insert their tokens into the same search box and share the search modal's query
parser, so `in:` filters to a note and its subtree and `when:` bounds the
last-modified date (Before / On / After / Between, via a compact date builder).

## Emoji reactions — picker rework

- **Five, then eight quick presets** — the picker leads with a small preset row
  (happy / sad / tada / angry / surprised, plus looking / thumbs-up / green-check)
  spread across the popover, with everything else reachable through search.
- **Live search** — type a name (colons optional: `:cat:`, `cat`, or a partial
  `ca`) and matching emoji appear as you type, ranked exact → prefix → substring.
  Enter inserts the first result (a typed literal emoji wins).
- **Mobile picker is a full modal** instead of a floating popover, so the soft
  keyboard opens below the search field instead of lifting a mid-screen popover.
- **Fixes:** the reaction button no longer drops below long / multi-line notes on
  mobile (it now has its own slot in the row's action layout); the reaction chip
  shown after selecting is tightened to match the neighbouring buttons' height;
  and the desktop popover's search placeholder is no longer clipped.

## Other fixes

- **Snooze reminder toast** no longer overlaps its own text on mobile.
- **Header note** is collapsed to a single line by default with an expand /
  collapse toggle.
- **Store-lint:** removed a dead `eslint-disable` directive in a view's
  `setState` that the community-plugin review flagged.
