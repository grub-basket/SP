Attachments now follow their note when the composer destination changes, cut and copy no longer pay a cross-vault cost they rarely need, and several notices stop claiming things Stashpad cannot actually know.

## 0.211.9

- The README's outliner section said a single click enters a note. Entering a note is a **double**-click; a single click only selects. The quick-start section already said this correctly, so the two halves of the README disagreed.
- Recurring tasks are now labelled experimental in the settings Help tab too — both in the features list and in Known limitations — matching the labelling already present in the README and the repeat picker. Repeat rules work, but they are not thoroughly tested across time zones, missed occurrences, or multi-device sync, and should not be relied on for anything with real consequences.

## 0.212.0

- Cross-vault notices and modals now **bold** the note and vault names instead of quoting them, and always name BOTH the source and the destination vault. Previously several of them named only one end, or neither.
- The inline renderer that draws `**bold**` and `` `code` `` in toasts is now shared with confirmation modals, so both surfaces format identically. It builds text nodes only and never assigns HTML, so a note title containing markup stays inert.
- Swept every cross-vault site: the stamp-failure notice, the oversize-selection modal, the untrusted-source confirm, the receiving-progress notice, the "originals still exist" line, the paste-failure notice, the delete-the-originals confirm, the finished-the-cut receipt, and the cleanup-failure notice.

## 0.212.1

- The text importer gains a per-row **merge** toggle, matching the web importer. A merged row stops being its own note and becomes body text of the row above — the way to keep a code block, a wrapped paragraph, or a stray list item in one note when the parser splits it. Consecutive merges fold into the same target, and children of a merged row reattach to it.
- Fixed the per-row nest and outdent buttons, which changed only the preview's indentation. The import reads a note's resolved parent, not its displayed depth, so a note still landed under whatever parent the parser originally chose: the control appeared to work and silently did not. Levels and parents are now re-derived after any change made in the preview.
- Merged rows render muted, aligned to their target, with their nest, outdent and colour controls disabled — they no longer have a level or colour of their own. The Import button counts the notes that will actually be created rather than the rows on screen.

## 0.212.2

- Dropping an image into the composer now leaves the composer focused, with the caret after the inserted link. Writing the attachment triggers a re-render that rebuilds the composer, which discarded the focus while keeping the text — so the file attached correctly but typing still required a click. Covers dropping onto the composer, dropping onto the attachment button, and pasting an image.

## 0.213.0

- An attachment added in one folder's composer now follows the note when the destination is changed to another folder, instead of being left behind in the folder it was dropped in. Links are rewritten to match.
- Only files staged by that composer, and referenced by nothing else, are moved. A link pasted from elsewhere, or a file another note embeds, stays where it is and keeps a link that still resolves.

## 0.213.1

- The repair pass now re-homes attachments stranded in the wrong folder: a file referenced by notes in exactly one folder is moved to that folder.
- An attachment shared across SEVERAL folders is deliberately left alone and reported instead. There is no single correct home for it, and moving it would break the other folders' notes.
- Unreferenced attachments are left untouched.

## 0.213.2

- Deleting a Stashpad folder now warns first when notes in other folders embed attachments stored inside it, naming the affected folders and stating the consequence — the notes survive, the images stop resolving. The confirm defaults to Cancel in that case.
- Deleting a folder through Obsidian's own file explorer cannot be intercepted, so Stashpad now reports immediately afterwards which notes lost their embeds, and points at the trash as the way back.

## 0.213.3

- Re-homed attachments keep their full path in links. Obsidian's automatic link updating rewrites links to the shortest form, which reintroduces ambiguity when two attachments in different folders share a filename. Links are now rewritten explicitly, and the pass no longer depends on the "Automatically update internal links" setting.

## 0.213.4

- The folder-delete warning lists the specific shared attachments rather than only counting them. These are exactly the files no automatic re-home can resolve, so the decision is the user's.

## 0.214.0

- Cut and copy no longer build the cross-vault transfer bundle. Building it reads every note and every attachment in the selection, and that cost was paid on every cut and copy for a feature used occasionally — slow on a large selection or a network drive. Same-vault cut, copy and paste are now as fast as a plain text copy.
- Two new commands, **Copy for another vault** and **Cut for another vault**, prepare the transfer deliberately. Both appear in the command palette, in the right-click menu, and in Stashpad's hotkeys settings; neither has a default chord.
- Pasting is unchanged: Stashpad detects a cross-vault payload on the clipboard automatically, so the usual paste shortcut still handles both cases.
- Note that copying in one vault and pasting in another now requires the new command first.

## 0.214.1

- "Stashpad: syncing — list updates paused until it settles…" now reads "lots of files are changing". The check behind it only knows that many file changes arrived at once, which Obsidian Sync causes — and so do an import, a bulk paste, a folder move, another plugin writing, or a re-index. Claiming Sync sent people to check Sync settings for a problem that was not there.
- "A newer Stashpad build synced in" now reads "A newer Stashpad build is installed", for the same reason: a new build also arrives via BRAT, a manual install, or the community-plugin updater.
- Four events that previously used plain notices now appear in the notification history: the cross-vault prepare failure, the cross-vault paste failure, and both "kept N attachments, still used by other notes" messages. Failures are the ones most worth having a record of.

## 0.214.2

- Files listed in a confirmation dialog are now clickable and open when selected, and the list has its own scroll region. A folder holding many shared attachments could previously have grown the dialog past the screen and pushed its buttons out of reach. The folder-delete warning now lists every affected file rather than a sample.
- New setting, off by default: **Always prepare cut/copy for another vault**, which restores the previous behaviour of preparing the transfer bundle on every cut and copy. Worth enabling on a fast machine where the cost is unnoticeable.
