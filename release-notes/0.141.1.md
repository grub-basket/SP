# 0.141.1 — Per-folder encryption keys

Encryption key storage moves off a single shared file and onto per-folder key
files, making encryption far more robust on synced and network-drive vaults.

## Per-folder encryption keys (0.141.0 – 0.141.1)

Previously every folder's encryption key lived in one shared file
(`.stashpad/keys.json`) that syncs across devices — so two devices (or two
windows) changing keys at once could clobber each other, and a sync client writing
that file mid-operation could corrupt it.

Now **each encrypted folder stores its own key in a `.stashkey` file inside the
folder**, travelling with the content it protects. There's no shared, cross-folder
file to race on.

- **Automatic + safe migration.** Existing folders move to the new format on load
  — it's a copy of the already-wrapped key (no decryption, nothing re-encrypted),
  verified before it's trusted, and the old key file is kept as a backup, so the
  change is fully reversible.
- **Password changes stay instant** — changing a folder password re-wraps the key
  in place; your notes are never re-encrypted.
- **Network-drive / shared-folder friendly** — the key file is written atomically
  (write-then-rename), and a shared folder password naturally works for everyone
  who has it.

Existing encrypted content continues to decrypt exactly as before — only *where
the key is stored* changed.

## Hardened key-file writes (0.140.18)

The vault key file is now written atomically (to a temp file, then renamed into
place), so a crash or sync client writing mid-operation can no longer corrupt the
live key file. (This also underpins the per-folder `.stashkey` writes above.)
