# 0.537.2

This release covers every change since 0.536.1. A folder that looks empty because filters are hiding its notes now says so, and the day, author and imported-only filters are kept after a restart. On slow or network drives, Stashpad checks the list again once Obsidian has finished reading the drive. The "lots of files are changing" notice now appears only once, no matter how many Stashpad tabs are open.

## Updates

- **0.537.0** — Tells you when filters hide every note, and re-checks folders that load before the drive has been read.
  - When the active filters hide every note in a folder, the list no longer shows **This Stashpad is empty** with its **Load example content** button. That button could add example notes to a folder that wasn't actually empty.
  - Instead, the list says how many notes are hidden, names each active filter (day, time range, tag, colour, author, imported only, hide completed, hide notes without children, attachments only, find), and offers a button that clears them. The filter bar isn't shown in compact mode on desktop, so this is often the only place an active filter is visible.
  - The clear button turns off the chip filters and the per-folder toggles (hide completed, hide notes without children, attachments only). Find is listed but not cleared, because its own bar is already on screen.
  - On a slow or network drive, a Stashpad tab can open before Obsidian has finished reading the folder, so the first list comes up short. Stashpad now waits for Obsidian to finish reading the vault, then reloads the list if notes on disk are missing from it. This runs when a tab opens, when a tab is restored at startup, and when a tab switches folders.
  - The existing background check skipped its turn while Stashpad was busy with a large batch of changes. This new check waits and tries again (every 1.5 seconds, up to 20 times). A tab in the background gets the check when it's next shown.
  - While that first wait is in progress, an empty list says **Still reading notes from disk…** instead of calling the folder empty.
- **0.537.1** — One **lots of files are changing** notice instead of one per tab.
  - Each open Stashpad tab, including background tabs and pop-out windows, used to show its own copy of **Stashpad: lots of files are changing — list updates paused until it settles…** during a sync or bulk change. Several tabs meant several identical notices.
  - The notice is now shared. It stays up while any tab is paused, and closes about 1.5 seconds after the last one settles. If another burst starts within that time, the same notice stays up instead of closing and reopening.
- **0.537.2** — The day, author and imported-only filters are kept until you clear them, and the "hidden by filters" message is easier to spot.
  - These three filters used to be dropped when Obsidian restarted with the tab already open, then come back the next time the folder was opened fresh. That made a folder look empty at seemingly random times. They're now kept after a restart, like the tag, colour and time filters.
  - The "hidden by filters" message is now a highlighted card: a filter icon, a large **N notes are hidden by filters** heading, a line saying the folder isn't empty, the active filters shown as coloured chips, and a **Clear all filters** button.

## Internal

- New `healTreeAfterIndex` uses the existing `whenVaultIndexed` helper. It only reloads the list when the tree has fewer notes than are on disk; the opposite case belongs to the existing check, which handles notes that were just created. It logs a `reconcile:index-ready` entry to the debug trace.
- `countNotesOnDisk` is pulled out of `scheduleTreeReconcile` so both checks count notes the same way. The existing check behaves exactly as before.
- The shared notice lives on the plugin (`holdSyncBurstNotice` / `releaseSyncBurstNotice`) and is closed when the plugin unloads. Each tab still decides on its own when to pause and resume list updates.
- `getState` / `setState` now save and restore `dateFilter`, `authorFilter` and `importedOnly`. Values are checked the same way as the per-folder filter cache. Workspace state from older builds, which doesn't have these values, leaves them unchanged.
- Merged the fix branch into main. The only conflict was the version number in `manifest.json` / `package.json`.
- Developer changelog notes for the branch. They don't ship in the plugin.
