# 0.252.0

Two strands: the Stashpad-app importer became safe to run — and safe to run
twice — and three long-standing annoyances in the note list were fixed.

## Importing from the Stashpad app

The importer was rebuilt around the assumption that you will run it more than
once, on a vault that already has notes in it.

- **Note ids can no longer be destroyed by YAML.** An id that YAML would
  reinterpret (as a number, a boolean, a date) could be silently rewritten on
  the next frontmatter write, detaching the note from its place in the tree.
  Ids are now written in a form YAML cannot reinterpret.
- **Re-running an import no longer duplicates anything.** Existing section
  parents are reused rather than rebuilt, reference notes are left alone, and
  notes already imported are skipped.
- **Choose where the import lands**, including a nested path, with a
  confirmation step before anything is written. The picker offers real folders
  and a "New folder" option, and never reserved ones.
- **The app's own root notes are kept** instead of being replaced.
- **Adoption refuses to touch a note that already has an identity**, so an
  import can never claim a note that was already yours.
- **Progress is reported** — including during the linking phase — and the
  window keeps painting while the import runs, instead of freezing until it
  finishes.
- Counts in the summary reflect what actually happened.
- The importer disarms the drop-watcher while it works, so its own file writes
  are not mistaken for you dropping files in.

## Fixed: the code-block copy button did nothing

Every code block in a note showed Obsidian's copy button, and clicking it had
no effect.

The button was real and correctly placed — it was **inert**. Note bodies are
re-rendered from a cache of previously generated HTML, which reproduces the
button's markup but not the click handler Obsidian attaches when it renders a
block live. The click is now handled directly, so the button works from the
cache. It copies the code only, never its own label, and flips to a tick to
confirm.

## Fixed: the "internal links are off" reminder only ever appeared once

Obsidian's **Automatically update internal links** setting being off is a
genuine hazard for Stashpad: it renames a note's file when the first line
changes, and with that setting off Obsidian will not repoint `[[links]]` to the
renamed note, so they break silently.

The warning was shown once and then never again, while the problem carried on.
It now reappears each time Obsidian starts for as long as the setting is off,
and stops on its own the moment you turn it on.

## Fixed: copy menus did not admit they were adding timestamps

With **Prefix timestamps when copying** enabled, the menus still read "Copy"
and "Copy tree", and the confirmation previewed plain note titles that did not
match what had actually been copied.

Both menus now read **Copy with timestamps** / **Copy tree with timestamps** /
**Copy text with timestamps** when the setting is on, and the confirmation
shows the timestamped form. *Copy outline* is deliberately unchanged — it does
not add timestamps, so relabelling it would have introduced the same mismatch
in reverse.
