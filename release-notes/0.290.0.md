# 0.290.0

Performance: large folders no longer freeze on edits.

## The problem

In a folder with a few hundred notes, editing a note, ticking a checkbox in a
note's body, or typing could lag badly — the whole list re-rendered on every
change, blocking the UI. On a 400-note folder a single edit could freeze the app
for many seconds.

## What changed

- **Editing a note now repaints just that one note**, not the entire list. The
  edited row's body updates in place (the old body stays visible until the new
  one is ready, so there's no flash), and the rest of the list doesn't move.
  This covers edit-modal saves, external/synced edits, and typing.
- **Ticking a checkbox in a note's rendered body** no longer rebuilds the list —
  so it no longer jumps, and (combined with the 0.289.0 fix) it toggles and
  saves correctly.
- **Creating and deleting notes no longer flicker.** A newly created note briefly
  left the in-memory tree one ahead of what was on disk, which triggered a
  redundant rebuild — that's what made deleted notes appear to vanish, come back,
  and vanish again. Fixed with a short grace window so the counts settle without
  a rebuild.

Creating a note in a very large folder still does one full render (further
incremental-insert and windowed rendering are the next steps), but the cascade of
re-renders that used to follow each create is gone.
