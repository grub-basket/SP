This release completes a major reworking of Stashpad's encryption into a **strictly
per-folder** model, and folds in composer and note-creation improvements.

## Encryption is now fully per-folder

Stashpad encryption no longer uses a single vault-wide password or a central key
file. Each encrypted folder owns its own password and key, stored in a `.stashkey`
file *inside that folder* (so the key travels with the content it protects). A
folder with no password of its own — and no encrypted parent to inherit one from —
is simply not encrypted. This removes the whole class of sync conflicts a shared
central key file could cause, and makes sharing a single folder straightforward:
hand over that folder's password.

Existing vaults keep working: any legacy central key file is still read for
backward compatibility and its folder keys migrate to the new per-folder format
automatically. Once everything has migrated, a new settings action lets you retire
the old key file.

---

### 0.142.0

- Removed per-folder key **rotation**. Changing a folder's password is now always a
  fast in-place re-wrap of the existing key; there is no separate re-encrypt-all
  "rotate" pass. To fully invalidate a key, remove the folder's encryption and
  re-encrypt it under a new password.

### 0.142.1

- Added an optional **recovery password** per folder — a second password that also
  unlocks the folder, as a backup if the main one is lost. Manage it (add / change /
  remove) from the per-folder encryption settings.

### 0.142.2

- Removed the device-approval "Collaborators" UI (member lists and join
  requests). Sharing an encrypted folder is done by sharing that folder's password
  out-of-band. Content that was already unlockable stays unlockable.

### 0.142.3

- A folder can now be given its **own password without first setting up vault-wide
  encryption** — per-folder encryption stands on its own. Setting a folder password
  can be the first (and only) encryption in a vault.

### 0.142.4

- Encryption settings copy clarified for the per-folder model (a vault with only
  per-folder passwords no longer reads as "not set up").

### 0.142.5

- Note IDs are now **de-duplicated at creation** — Stashpad never mints an ID that
  already exists in the vault, closing a rare collision window.
- Composer: toggling the Enter-mode (send vs. newline) no longer re-renders the
  whole note list.

### 0.142.6

- Composer: split-mode toggles now update the composer **in place** instead of
  triggering a full list re-render.

### 0.142.7

- Composer button row reordered; mobile layout reworked so the buttons no longer
  overlap; the current destination is shown in place.

### 0.143.0

- Encryption is now **strictly per-folder**. The vault-wide password, the shared
  password, device identities, and the central-key-file unlock path are all
  removed. A folder with no password of its own (or inherited) is not encrypted —
  there is no vault-wide fallback key. Legacy key files remain readable for
  backward compatibility, and their folder keys migrate to `.stashkey` files.
- The top-level Encryption settings are reduced to a single content-based **"Remove
  all encryption"** action; passwords are set, changed, and recovered per folder.
- Notes are no longer auto-unlocked at startup — each folder unlocks on demand
  (silently, from the keychain, if you chose to remember it there).

### 0.143.1

- The **"Remove all encryption"** action is hidden when nothing is encrypted.
- Fixed unlocked notes whose titles were hidden while encrypted showing as
  "(untitled)" — the re-encrypt review dialog and the "Previously encrypted" view
  now resolve the note's real (now-readable) title.
- The **"Remember on this device"** checkbox in the password dialog is now checked
  by default (untick it to require re-typing).
- Added "(lock)" to the **"Encrypt & delete"** and **"Encrypt everything
  applicable"** command names for discoverability.
- The per-folder **"Folder"** picker is now a heading-sized selector.
- New command **"Delete selection to Obsidian's trash (unencrypted)"** — deletes
  the selection through Obsidian's own trash, bypassing encrypted-trash.
- Notifications now carry **jump buttons**: the secure-delete notice offers "Open
  Trash", and restore notices offer "Go to folder".

### 0.143.2

- New manual, reversible **"Retire the old encryption keyfile"** settings action
  (shown only when a legacy key file is still present). It moves the old key file
  and its backups into a dated `retired-keyfile-…` folder — nothing is deleted —
  and refuses if any folder's key still lives only in the old file.

### 0.143.3

- The retire action now verifies each parked file byte-for-byte before removing the
  original, so an interrupted or truncated write can never leave a corrupt backup.

### 0.143.4

- The **"Delete (unencrypted)"** command routes to Obsidian's own trash (system
  trash or `.trash`, per your Obsidian setting), keeping deleted items out of any
  folder's encrypted trash.
