# 0.208.5

Covers everything since 0.206.1. The headline is the new-user experience: opening
Stashpad for the first time now asks before it writes anything, explains what a
Stashpad is, and can load example content so the idea lands immediately.

## 0.207.0 — line numbers in the editor

- Line-number gutter in the note editor, plus a logical line count in the stat
  row. New setting "Line numbers in the editor" (on by default, desktop only).
- Numbers stay aligned through soft wrapping. A textarea has no gutter and no way
  to report where a line was drawn, so each number is positioned by measurement —
  a hidden mirror with the textarea's exact width, font and padding renders every
  logical line and each number takes that line's real height. A naive
  one-row-per-line gutter desyncs the moment any line wraps, which in a note
  editor is immediately.
- Fixed during testing: the gutter had no definite height, so it stretched to fit
  its own numbers — `scrollTop` pinned at 0 and a long note would have dragged the
  modal taller. It now takes the textarea's `clientHeight`.

## 0.207.1 — one canonical list of per-folder sidecar files

- `STASHPAD_SIDECAR_FILES` in `types.ts` is now the single source of truth for the
  dotfiles Stashpad keeps beside a folder's notes; `order-store`, `sort-store` and
  `structure-snapshot` derive their filenames from it, so the documented list
  cannot drift from what is actually written.
- Enumerating them surfaced a fourth sidecar that no from-memory list had
  included: `.stashpad-sort.json` (per-parent sort mode).
- The interop documentation gains the sidecar table, per-file guidance for tools
  converting a Stashpad folder, and a note that these files are written through
  the adapter rather than the vault API.

## 0.208.0 — first-run experience

- **Welcome on first run.** Enabling Stashpad previously added ribbon icons and no
  greeting, and the first click silently created a folder, a Home note and two
  subfolders with no prompt. A welcome now appears first: it explains what
  Stashpad is, takes a folder name (defaulting to `Stashpad`), and offers "Set up
  later" (which writes nothing), "Set up fresh", or "Set up with demo content".
- It appears only when there are **no** Stashpad folders yet and only until it has
  been answered once, so existing vaults are never interrupted. Dismissing counts
  as answering.
- **Example content.** A 34-note demo tree — a trip, a reading list, recipes,
  tasks with due dates — can be created from the welcome, from the command palette
  ("Create example content in a new Stashpad"), or from the empty-state button.
  They are ordinary notes with ordinary ids and filenames, editable and deletable
  like any other.
- **A real empty state.** An empty Stashpad root now explains what the pane is,
  what the composer does, and offers buttons for example content and the
  walkthrough. Drilling into a note with no children keeps the previous quiet
  one-liner.
- **Folder creation is announced.** Opening a view that creates a folder now says
  so, naming the folder and noting the contents are ordinary markdown.
- **Help & Getting started settings tab.** Explains what a Stashpad is, lists
  features, lists every command with its default chord (generated from the command
  table, so it cannot drift), states known limitations, and shows the version with
  a link to the repository. The explanation of what a Stashpad is previously
  existed only inside a search-scope setting and disappeared once a folder existed.
- Folder names typed into the new field are rejected if they contain `.` or `..`
  path segments; the same guard was added to the existing "create a Stashpad"
  path, which had none.
- Commands "Getting started (welcome / setup)" and "Create example (demo) content
  in a new Stashpad" make onboarding reachable at any time.

## 0.208.1 — first-run fixes

- The empty state's "Load example content" now fills the folder being viewed
  instead of creating a separate one and navigating away from it.
- The demo folder's Home note is named to the same convention as every other Home
  note, so a newly created demo folder no longer renames one of its own files the
  first time it is opened.
- Seeding never overwrites: a path that already exists is skipped and counted.

## 0.208.2 — one rule for opening a Stashpad

- The ribbon icon and the "Open Stashpad in new tab" command previously used
  different folder-count rules, so with exactly one Stashpad the ribbon opened a
  picker containing a single entry while the command opened the folder. Both now
  follow one rule: no folders shows the welcome, one folder opens it directly, two
  or more show the picker. Right-clicking the ribbon still always shows the picker.
- The folder switcher ranks the folder you were last working in first.
- The ribbon icon changes from a file-tree to stacked rectangles, which reads as a
  pile of notes rather than a filesystem.

## 0.208.3 — no more stray default folder

- Opening a Stashpad no longer creates an empty `Stashpad/` folder alongside it.
  View state arrives after a view opens, so for one moment the view resolved to
  the default folder and created it before switching to the real one. Long-standing,
  and newly conspicuous now that folder creation is announced.

## 0.208.4 — clean titles

- Breadcrumbs, the focused header, crumb tooltips and the tab title no longer show
  raw Markdown syntax. A note beginning `**Atomic Habits** — James Clear` displayed
  its asterisks, because titles come from the note's first heading or first body
  line verbatim.
- Emphasis, inline code, strikethrough, highlight, links, images, wikilinks
  (showing the alias when present), leading block markers and backslash escapes are
  all handled. Stripping is deliberately conservative, so `snake_case_name`,
  `a_b_c`, `2 * 3 = 6` and a trailing `5 stars ***` are left alone.
- Notes are unchanged on disk — this affects display only.

## 0.208.5 — deep-link paste

- The "Open Stashpad link" dialog reads the clipboard through Electron rather than
  the browser clipboard API. The browser API rejects when its document is not
  focused, so automatic pasting worked in some windows and silently never happened
  in others — most visibly in secondary windows when several vaults were open.

## Internal

- Test tooling: a third isolated test vault for exercising the first-run path
  (which needs a vault with no Stashpad folders), a slot table replacing hard-coded
  pairs so an explicitly requested slot can never fall back to a different vault,
  and a window-focus helper.
- The in-app testing banner gains readable contrast and no longer dismisses itself
  when clicked.
- Branch changelogs, the editor input-parity notes and the interop document were
  updated alongside the changes above.
- A change dropping the folder panel's "new folder" button was reverted in the same
  cycle — the button is unchanged from 0.206.1.
- Release notes for 0.206.1 were rolled up after that release.
