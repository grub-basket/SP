# 0.270.0

Covers everything since 0.268.18: a new setting for where Stashpad notes open, a
fix for tabs closing when they should not have, and pinning a note to the bottom
of its list.

## 0.269.0 — Open Stashpad notes in Stashpad

A new setting, **off by default**. With it on, a Stashpad note that lands in an
ordinary editor tab — from the quick switcher, a wikilink in another note, the
file explorer, a search result — is taken out of that tab and shown inside
Stashpad instead. It saves finding your way back after Obsidian's own navigation
drops you in the editor. It is off by default because it changes what a very
ordinary action does, so it should be chosen rather than inherited.

Two things shape the design, both solved structurally rather than with timers,
because a race here would loop:

- **"Open in Obsidian editor" still reaches the editor.** Every place Stashpad
  opens an editor on purpose stamps that tab first, bound to the file it was
  granted for, and the router honours the stamp. Being a property of the tab, it
  holds across however many events fire; being bound to the path, a wikilink
  followed from that tab is routed like any other.
- **The router cannot fight itself.** Redirecting opens a Stashpad view rather
  than a markdown file, so it never re-enters. It redirects first and closes
  after, re-checking in between — if revealing fails the editor tab stays, so
  you are never left with nothing open.

Third-party switchers all bottom out in the same underlying event, which is what
makes it the right hook — it is not tied to any one way of opening a note. Not
intercepted: a tab that already held the note, a tab that is not the focused one,
and notes that are not Stashpad notes.

## 0.270.0 — Tabs no longer close out from under you

The exemption described above could be lost, and when it was, the wrong tab
closed:

- Opening a note in the Obsidian editor from a popped-out edit tab worked, then
  the **editor** tab closed a few seconds later.
- Closing the Stashpad tab afterwards closed the **popped-out editor** instead
  of the tab that was clicked.

Three defects combined to cause it, all in the routing logic:

- The record of which file a tab last held was only written as the very last
  check. A tab Stashpad opened itself was exempt, and so returned before ever
  being recorded. Once its exemption lapsed, the "this tab already held this
  note" check had nothing to compare against and the tab was treated as a fresh
  open. It is now recorded for every note opened in an editor tab, before any
  of the checks that can return early.
- The exemption was cleared whenever *any* file-open event arrived while the
  stamped tab happened to be focused — including the event Obsidian fires with
  no file at all when a tab closes. Closing an unrelated tab was enough to strip
  a tab's exemption. Fileless events are now ignored, and the exemption is
  cleared only when that tab itself moves to a different note.
- Both handlers assumed the focused tab was the one the event was about. When a
  tab closes and focus shifts, the focused tab is simply whichever tab inherited
  focus — which is exactly the case that closed the wrong one. Both now require
  the focused tab to actually be showing the note the event refers to.

## 0.270.0 — Pin a note to the bottom of a list

The list pin previously floated a note to the top of its list. It can now hold a
note at the **bottom** as well — for a note that belongs with a list without
belonging at the front of it: a summary, a parking spot for loose ends, a
reference you want to land on after everything else.

- The right-click menu is now **Pin in list**, with **Top of list** and **Bottom
  of list** inside it (a checkmark shows where a note is currently pinned) and
  **Unpin from list** once it is pinned. Choosing the opposite end moves the pin
  rather than removing it.
- Both ends are available as commands and as bindable actions: *Pin / unpin to
  top of list* and *Pin / unpin to bottom of list*. Neither has a default chord.
- A bottom pin's badge shows the pin pointing down, so the two read differently
  at a glance.

**Pinned notes now ignore the time filter.** A pin is a deliberate "keep this
here", so a pinned note stays in place as the time window slides — which is the
point of pinning a reference note to the bottom of a list you filter by day or
week. The content filters (tag, colour, author, and the rest) still apply: those
mean "show me only these", where quietly including something that does not match
would be wrong.

Notes pinned before this release are unaffected and keep their position at the
top.
