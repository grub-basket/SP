# 0.147.0

## Deep links — `obsidian://stashpad?…`

Stashpad now registers a handler for the `obsidian://stashpad` URL, so you can build
shareable links that route straight into the Stashpad view and land on a specific
note. The links are plain URLs, so they are copy-pasteable, survive across machines,
and work from anywhere the OS can open a URL — another note, a chat message, a
Shortcut, or `open "obsidian://…"` from a terminal.

### Copying a link

- New command **"Copy Stashpad link (deep link / URL) to note"** — copies a link to
  the cursor row (or the first selected note) and confirms with a notice. It has no
  default hotkey; assign one in Stashpad's settings if you want.
- New **"Copy Stashpad link"** item in a note row's right-click menu.
- Links reference the note's stable internal `id`, not its filename, so they keep
  working after the note is renamed.

### Link format

```
obsidian://stashpad?vault=<name>&folder=<folderPath>&note=<id>&run=reveal
```

- `vault` (optional) — Obsidian switches to this vault if given; omit to use the
  active one.
- `folder` (required) — the Stashpad folder to open.
- `note` (optional) — the target note's `id`; omit to just open the folder.
- `run` (optional) — an ordered, comma-separated macro run after the note is
  revealed. Vocabulary in this release: `reveal` (the default — open the folder and
  select the note) and `open` (also open the note's Markdown file in an editor pane).
  Unknown tokens are skipped rather than aborting the whole link.

### Behaviour

- Opening a link reuses an existing Stashpad tab already on that folder instead of
  spawning a duplicate.
- If the folder or note in a link can't be found, Stashpad shows a clear error notice
  rather than silently doing nothing.
- Cross-vault links wait for the workspace to finish loading before revealing, so a
  link that switches vaults still lands on the right note.
