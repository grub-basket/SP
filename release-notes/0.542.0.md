# 0.542.0

This release covers every change since 0.541.1. A Stashpad link pasted into a note now shows and opens as one whole link, even when it contains underscores, asterisks or a note address.

## Fixes

- **0.542.0** — Pasted Stashpad links stay in one piece.
  - **Underscores and asterisks no longer break links.** A bare `obsidian://stashpad?…` link pasted into a note was formatted as Markdown before Stashpad made it clickable. An `*` anywhere in the link, or a pair of `_` or `__` at a word edge (for example a folder named `__Inbox__`), turned part of the link into italic or bold text. The link stopped at that point and the rest showed as formatted text. The whole link is now clickable, and the text is shown exactly as written.
  - **Links to a note now open that note.** In a pasted link, `&note=` was read as the HTML character code `&not` and shown as `¬e=`. This happened in the text you could see and in the address the link opened, so the link went to the folder without the note. Pasted note links now keep the note.
  - **Formatting you add still works.** A link wrapped in bold, italics or a highlight (`**link**`, `_link_`, `==link==`) keeps that formatting. Links inside inline code or code blocks stay as plain text. Links written as `[text](link)` or `<link>`, and links in tables, work as before.
  - **Existing notes fix themselves.** Notes that already contain a Stashpad link are drawn again the next time they appear. Other notes keep their saved rendering, so this costs nothing extra on a shared or network drive.

## Internal

- New `src/deep-link-markdown.ts`. `protectDeepLinks` swaps each bare `obsidian://` URL for a placeholder made only of letters and digits before `MarkdownRenderer.render`. `restoreDeepLinks` puts the original URL back afterwards, as an `a.external-link`, or as plain text inside a link, code or pre. It skips fenced code, inline code, `](…)` link targets, `<…>` autolinks and quoted HTML attributes. It only creates elements with `createElement` and `textContent`, and never inserts raw HTML.
- `NoteBodyRenderer` now runs one shared `renderMarkdown` for both the read and prime paths: protect, render, restore, highlight colors, then autolink.
- `RenderEntry.dlX` and `DEEP_LINK_RENDER_VERSION` mark a cached render as stale only if it has no stamp and its text contains `obsidian://`. The render cache format is unchanged.
- New unit tests in `scripts/tests/deep-link-markdown.test.ts`.
- Developer changelog notes for the branch. They don't ship in the plugin.
