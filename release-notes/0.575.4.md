# 0.575.4

This release covers every change since 0.573.3:
- **Enter saves** in the note edit window, and Shift+Enter adds a new line.
- **On a phone**, the edit window's buttons fit on one row.
- **"Attribute to AI…"** has moved into the Advanced submenu.
- **Pin labels** flip to "Unpin" straight away, including on mobile.

## Highlights

- **Enter saves in the edit window.** Press Enter (Return) to save the note you're editing. Press Shift+Enter for a new line. ⌘/Ctrl+Enter still saves too.
- **New setting: "Enter adds a new line when editing a note"** (Settings → Behavior → Composer & Editing). Turn it on and Enter adds a new line again, and you save with ⌘/Ctrl+Enter or the Save button.
- **On a phone, a Return button sits next to Save.** Phone keyboards can't type Shift+Enter, so tap it to make Return add new lines in that window, and tap again to make Return save. Your setting doesn't change, and your cursor stays put.
- **Edit window buttons fit on one row on mobile.** Cancel, Attach, Pop-out and Advanced show just their icons on mobile. Long-press any of them, or use a screen reader, to hear its name. Save keeps its word and fills the rest of the row.
- **"Attribute to AI…" is now in the Advanced submenu** of the note menu (⋮ / right-click), next to "Open in Obsidian editor", "View history" and "Split note…".
- **Pin and Unpin wording updates right away.** After you pin a note to the sidebar, the menu says "Unpin from sidebar" straight away, even on a phone. Before, it could keep saying "Pin" for a few seconds, and tapping it again then did nothing. The quick ★ menu and note buttons also show the right word now.
- **Fixed a pop-out window bug.** With a pop-out window focused, a notification could show the text "[object DocumentFragment]" instead of its message.

## All changes

### 0.574.0
- The edit window (modal and popped-out tab, desktop and mobile) saves on a plain Enter. Shift+Enter adds a new line, and list continuation now runs on Shift+Enter. ⌘/Ctrl+Enter still saves.
- Some Enter presses do something else first, so they don't save: picking from the `#` / `[[` / `@` autocomplete list, adding a row in a Markdown table, or confirming text in an input method (IME).
- Holding Enter down saves only once, so a held key can't save the next note in a multi-note edit queue.
- New setting `editEnterNewline` ("Enter adds a new line when editing a note", Behavior → Composer & Editing), off by default.
- The help line and a new hint on the Save button show the current keys: "Save (↵)", or "Save (⌘↵)" / "Save (Ctrl+↵)".
- Mobile: a Return-mode button next to Save switches what Return does for that window only. It updates in place, keeping your cursor, selection, scroll position and undo history.
- Split mode is unchanged.

### 0.574.1
- Applies the store-lint cleanup from pull request #2 to the plugin's development source, so the source matches the built plugin again. It changes 27 files under `src/`: timers go through `window.*`; elements are created via `activeDocument`; `.instanceOf(HTMLElement)` replaces `instanceof`; redundant regex escapes are removed; and a few other small mechanical rewrites. eslint findings drop from 783 to 596.

### 0.575.0
- Mobile edit and split windows: Cancel, Attach, Pop-out and Advanced are icon-only. Their names are kept as the `aria-label` and the tooltip, and desktop still shows the words.
- Icon buttons are an equal 40px wide. On the edit surface, Save fills the rest of the row. On a 393pt-wide phone, the edit row fits on one line instead of two.

### 0.575.1
- Notification toasts, the Home-note preview notice, the tab-cleanup summary and the OKF setting descriptions build their content with Obsidian's `createFragment()`. A fragment from a focused pop-out window's document failed Obsidian's type check and showed "[object DocumentFragment]".

### 0.575.2
- "Attribute to AI…" moved from the top of the note menu into Advanced ▸. If you saved a custom menu order, a one-time update removes the top-level copy, but only once Advanced contains the item.
- Sidebar pin state is updated in memory as soon as you pin or unpin. Before, it was only read from Obsidian's metadata cache, which can lag by seconds on a phone. This affects:
  - menu labels
  - the "already pinned" and "already unpinned" checks
  - the sidebar's Pinned list
- The quick ★ menu and the row/item buttons show "Unpin from sidebar" for a pinned note, and the buttons update right after a tap.

### 0.575.3
- The in-memory pin state is now cleared only when Obsidian reports the file change it was waiting for. Before, a quick Pin then Unpin could briefly flip the label back to "Unpin".
- "Attribute to AI…" stays at the top level of the note menu if your Advanced submenu was renamed without it, or hidden, so it can't disappear. The settings menu editor shows the same list.
- Note buttons check pin state from one shared list per render, instead of scanning the vault once per row.
- On desktop, a row's pin button keeps its icon style after a tap, and the edit window's buttons show the same tooltips as before 0.575.0.

### 0.575.4
- Pin and Unpin wait for every pending write on the note before trusting Obsidian's cache again. Tapping Pin, Unpin, Pin in quick succession now stays "pinned" the whole time.
- The shared pin list used by note buttons refreshes after a pin from any menu, hotkey or bulk action, not only from the button itself.
