# 0.545.1

This release covers every change since 0.544.6. You can now choose how long notes collapse in the list, and how many lines a collapsed note shows on desktop and on mobile. **Nothing changes unless you change it.** The default, **Classic**, is the same preview as before.

## New

- **0.545.0** — Collapsed preview settings, under **Settings → List display**.
  - **How long notes collapse** has three options:
    - **Classic** (the default) is the preview you had before: the first lines of the note, ending in "…". Notes with a code block, table or callout show about 6 lines and can show part of an extra line.
    - **Whole lines** shows exactly the number of lines you set for every note, including code blocks, tables, callouts and quotes. It cuts cleanly at the end of a line, so you never see half a line. The last visible line fades out at its right end instead of showing "…". A note collapses only when it's longer than that many lines at the current pane width, and resizing the pane re-checks it.
    - **Count lines and characters** collapses a note that has at least a set number of non-blank lines, or at least a set number of characters, whatever the pane width. A note under both counts shows in full. It uses the same clean cut as Whole lines. On a wide pane, a note over the count can still fit, and then its **Show more** reveals nothing.
  - **Collapsed preview — desktop** and **— mobile** each have three boxes:
    - **lines** is how many lines a collapsed note shows.
    - **count lines** and **count chars** are the thresholds for Count mode.
    - The defaults are 2 / 3 / 300 on desktop and 2 / 3 / 150 on mobile.

## Fixes

- **0.545.1** — Fixes found in review:
  - Whole lines and Count now measure each note as it looks when collapsed. A collapsed note can wrap differently next to the row buttons than an expanded one, so measuring the expanded layout could have cut it mid-line.
  - In Classic, setting a line count other than 2 no longer gives short expanded notes a **Show less** that collapses nothing.
  - An embedded note inside a note is no longer treated as a single line of the preview.
  - The number boxes accept whole numbers only, and edits are saved even if settings reload while the settings window is open.

## Internal

- New `previewClamp` setting (`mode`: `classic` | `measure` | `count`, plus per-platform `lines` / `countLines` / `countChars`). An unknown mode loads as `classic`.
- `collectLineBoxes` reads the first N + 1 visual lines from `Range.getClientRects`. The cut lands at the bottom of line N, never below the top of line N + 1. It's applied as `--sp-clamp-h` through `setCssProps`, with a CSS mask for the fade.
- Classic keeps the previous `-webkit-line-clamp` rules under `.is-classic`, wrapped in `:where()` so each rule keeps its old specificity. It also keeps the previous scrollHeight measure (`measureClassic`).
- The cached overflow result now also stores the cut height, the last line's height and a fingerprint of the preview settings (`ovH`, `ovL`, `ovS`; `OV_MEMO_VERSION` 4).
- Developer changelog notes for the branch. They don't ship in the plugin.
