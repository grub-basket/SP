# 0.543.0

This release covers every change since 0.542.0. When a Stashpad folder disappears outside Stashpad, its tabs now act on what actually happened. A **renamed** folder's tab stays open and switches to the new name. A **deleted** folder's tabs close, as they did before 0.541.1.

## Updates

- **0.543.0** — Deleted folders close their tabs; renamed folders' tabs follow.
  - A rename made on another computer, for example on a shared network drive, reaches Stashpad looking exactly like a delete followed by a new folder appearing. So when a folder disappears, its tabs now wait about 10 seconds on the **This folder was moved, renamed or deleted** page.
  - If the folder turns up under a new name in that time, the tab switches to it and stays open.
  - If not, the folder is treated as deleted. Its tabs close and the notice says **Stashpad “…” was deleted — closed N open tabs**.
  - A folder that has never been opened on 0.541.0 or later has no folder ID yet. If there are also no recently used notes to recognise it by, a rename can't be told apart from a delete, so its tab closes. You can reopen the folder from the folder panel.

## Internal

- `handleStashpadFolderDeleted` waits `VANISHED_FOLDER_GRACE_MS` (10 seconds), then closes only the tabs still on the vanished folder (`closeStashpadTabsFor`). Tabs that followed a rename are already on the new folder and stay open.
- Developer changelog notes for the branch. They don't ship in the plugin.
