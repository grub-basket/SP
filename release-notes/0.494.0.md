# 0.494.0

Autocomplete release, plus two mobile keyboard fixes (0.493.0 and 0.493.1, released
here for the first time). **Every settings field that names a folder, tag, file
extension, timezone or callout now suggests as you type, and `[[` links written as
paths or with an alias typed first finally complete properly.**

## 0.494.0 — autocomplete everywhere

- **Shared suggester.** A new `StringSuggest` (`src/input-suggest.ts`, built on
  Obsidian's `AbstractInputSuggest`) and ranking helpers (`src/suggest-match.ts`)
  route all matching through Sift, Stashpad's search matcher, so suggestions match
  the same way search does. In comma-separated fields, only the item under the cursor
  is completed and replaced. Vault tags and file extensions are collected on the
  first keystroke, never at plugin load. Unit tests cover the ranking and
  list-item logic.
- **Settings fields that now autocomplete:**
  - "Watch only these folders" and "Mute these folders" suggest your Stashpad folders.
  - "Task tag chips" and "Task tag suggestions" suggest tags already used in the
    vault (without the `#`), with note counts.
  - "Display timezone" suggests IANA timezone names (`new york` → `America/New_York`).
  - "Link preview callout style" suggests callout types.
  - "File types to keep out of the media viewer" and "Companion files to encrypt"
    suggest file extensions found in the vault (`.md` is never offered for
    companions).
  - "Create a new Stashpad" suggests existing folders, as the welcome screen
    already did.
- **Note-template path** now uses Obsidian's standard suggester instead of a
  hand-built popover; Tab still completes one folder level at a time, and picking a
  note saves immediately.
- **Due/assign picker:** the "Add a tag…" box also offers every tag already used in
  the vault, after your configured tags.
- **Path-style links:** typing `[[Folder/Note` returned no suggestions at all,
  because matching only looked at note names, which never contain `/`. A query with
  `/` now matches the full vault path and inserts the path link (`.md` dropped,
  other extensions kept). Affects the composer, edit modal, detail composer and quick
  capture; plain `[[` and `@` queries behave as before.
- **Alias typed first is kept.** Writing `[[|alias]]` and then going back inside the
  brackets to search for the note used to erase the `|alias` when a suggestion was
  picked. The alias after the cursor is now read and kept: `[[Plan Alph|my alias]]`
  → `[[Plan Alpha|my alias]]`. An empty `[[…|]]` leaves the cursor in the alias slot.
- **Three pickers** — Import → choose folder, Decrypt a folder bundle, and Restore
  deleted note — matched on a single substring; they now use Sift like every other
  search.
- Fixed during testing: the first version of the new suggester used a property name
  (`isOpen`) that Obsidian's popup class already uses internally, so no popup ever
  appeared. Renamed before release.

## 0.493.1 — mobile after-send behaviour

- After tapping Send on mobile, the keyboard now settles closed by default (a calm
  collapse, no dismiss-then-reopen bounce).
- With **Focus composer after send** turned on, the keyboard now genuinely stays up:
  the composer is refocused inside the tap itself, which is the only moment iOS will
  re-show the keyboard. That setting previously had no visible effect on mobile.

## 0.493.0 — Send no longer dismisses the mobile keyboard mid-tap

- On iOS, tapping Send moved focus to the button at the very start of the tap,
  tearing down the keyboard before any existing guard could stop it. The Send
  button's touch guard now prevents that focus shift at `touchstart`. This is also
  the root cause of the older "double-tap opens the wrong note on long lists"
  report: send → keyboard dismisses → list reflows → a different row lands under
  your finger. Desktop is unchanged, and the long-press destination menu still works.
